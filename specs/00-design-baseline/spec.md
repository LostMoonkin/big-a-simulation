# P0 设计与工程基线

状态：未开始。规格版本：1.0。前置：[玩法设计0.2](../../docs/design/gameplay-market-model.md)及其研究。实施细节见[plan](plan.md)，具体任务见[tasks](tasks.md)。

## Goal

在正式实现前关闭会改变交易规则、资金行为、存档与验收方式的歧义。当前已有统一价批量竞价和多周期框架，但两市政策传导、资金特点和典型形态仍未定案；40股原型配额、数值实现和完整实验口径也需要固定。

交付后，开发者可以依据同一版本实现，审阅者能够从规则、算例和预期结果判断对错。P0不宣称市场已经好玩或经济已经稳定。

## Behavior

- 给出两个虚构市场的可区分机制：政策如何改变公开预期、经营/估值渠道、资金配置与报价；差异不是只改市场名称和持有期。
- 给出各市场的成立、落空和资金不足场景，说明玩家在何时能知道什么、如何承担风险；不通过预制K线证明形态。
- 明确价格保护、无成交和重开之间的顺序，处理现规则特别重开与连续涨跌停体验之间的冲突。
- 定义正式200股与原型40股两套可生成配额；原型沿用同一机制和26钱包，不任意删股破坏行业/概念关系。
- 冻结账务精度、命令/公开信息/快照合同和世界时钟；任何缓存或续季不会凭空增加现金、股份或历史。
- 明确默认新局快速进入的种子与初始化方案；可以现场计算或加载完整预热快照，不以页面出现进度条代替可交易。
- 给出可执行的阶段验证协议、固定场景和种子分组方法，明确待验证目标与已完成证据的差别。

## Constraints

- 以[精确规则](../../docs/design/market-model-rules.md)为起点；需改变时更新规则版本和受影响案例，不在实施spec内静默覆盖。
- 价格仍由有资源支持的有效委托形成，NPC只读公开信息和自身账户；不能按故事阶段直接给价格加涨跌幅。
- 首版正式规模、250日预热/赛季、跨季连续性、技术分析边界与后置范围保持[总览](../README.md)所列。
- 工程选择以现有技术研究为依据；新引入依赖应有官方资料、锁定版本、许可和针对当前需求的能力验证。
- P0的性能目标是计划阈值；必须标明测量设备和方法，不写成实测结论。

## Out of Scope

完整游戏、真实金融数据接入、完整现实交易所复刻、对技术理论预测能力作有效性背书；为后续衍生品建立泛化系统。

## Acceptance Criteria

| ID | 可验收结果 | 证据 |
|---|---|---|
| P0-AC1 | 范围、权威文档及冻结版本明确；P1/P2/P3所依赖的决策项没有“实现时再决定”的关键空白 | 决策清单、影响表与修订后的规则 |
| P0-AC2 | 两市各有完整政策/预期/资金传导图、参数表及至少2成立+2失败/反向场景；每个状态变化写明来源、公开时点和可检验方向 | 市场特色设计及场景数据；不能以指定最终股价作正确答案 |
| P0-AC3 | 价格保护阻断、有交叉需求与根本无供需三类情况有确定动作；规则与A13/A14及形态验收无冲突 | 开盘/日内/跨日重开状态表和固定反例 |
| P0-AC4 | 原型每市20股、6行业、4大/7中/9小、5无概念/11单概念/4双概念的约束可同时满足；正式100股配额保持原合同 | 完整40股配置样本、自动或手工可复核校验结果、正式/原型参数对照 |
| P0-AC5 | 金额、股份、乘法上界、费用舍入、随机流、近似数学和序列化方案明确；核心/CLI/Worker的同输入试验可比较且已知差异有处置 | 数值合同、小型技术试验及黄金样本；完整跨浏览器复现待P5 |
| P0-AC6 | 预热、报告/费用/复核相位、20日期望到期、跨季事件链和完整快照合同互相一致；公开决策窗口可暂停保存，清算与记账原子提交 | 跨第250日的纸面/数据流程、更新与过期算例、两类安全快照时点 |
| P0-AC7 | 选定工具版本、图表小时/日K+MA+画线、Worker通信、静态构建及存档编码不存在未解决的方向性障碍 | 官方依据、许可清单及最小技术试验记录；并非游戏验收 |
| P0-AC8 | A01–A32、市场特色新增场景、经济筛查、种子分组和性能协议均有负责阶段、通过口径和证据要求；默认新局方案同时满足随机世界合同和可交易时间目标，任意种子现场预热单列 | 更新后的追踪矩阵、实验协议与基准设备档案；默认开局/快照方案及一致性校验合同 |

## Notes

P0关闭的是设计歧义。它不能通过只写一张上涨K线或只给参数换名证明双市场特色，后续仍须P3因果对照与P5保留种子验证。
