# P6 执行任务

状态：全部未开始。拆分为 3 个可独立检查的交付切片：可复现静态产品、可直接使用的玩家/维护资料、最终包恢复演练。文档在本阶段本身是用户要求的交付成果，不拆成零散“补文档”任务。

## P6-T1 — 构建可独立启动的静态发布包

状态：未开始。

### Outcome

接手者从指定源版本构建出摘要一致的静态游戏，并能通过普通 HTTP 服务启动。

### Scope

1. 固定 P5 RC 的源、锁文件、工具和应用/规则/内容/存档版本，生成可搬运构建清单。
2. 两份干净输出构建并比较运行资产摘要，排除未记录本机输入与开发服务依赖。
3. 将静态文件、清单、摘要和构建/启动步骤放入版本目录，实施未来 `preview:release` 入口。
4. 在最终目录验证页面、Worker、图表、字体和内容加载，完成一次新局、交易及存读档；如采用默认完整预热快照，分发内容及重算一致性证据不得遗漏。

### Acceptance

- 满足 P6-AC1、P6-AC2；摘要和启动证据对应最终目录。
- 本地静态预览即可验收，不需要未知托管账号；不得以开发服务器替代。

### Depends On

- P5 候选版完成并冻结。

## P6-T2 — 交付规则、备份与版本资料

状态：未开始。

### Outcome

玩家能理解首版操作并自行备份进度，接手者能识别版本兼容及许可要求。

### Scope

1. 写入/更新快速开始、规则简化、本地备份恢复、支持浏览器和已知问题，按实际实现校对每个操作入口。
2. 完成版本页及用户主动复制/下载的反馈摘要，不默认上传存档或采集行为。
3. 汇总当前、上一兼容/迁移夹具、未知新版本与坏档的兼容行为说明，并关联可运行证据。
4. 审核所有游戏世界内容与示例，核对依赖、字体、图标及图表库许可/归属；打包适用通知。

### Acceptance

- 满足 P6-AC3、P6-AC4、P6-AC5；资料与最终实现一致，兼容结论来自夹具运行。
- 真实软件归属与虚构世界内容分开呈现，不能以虚构要求删除许可。

### Depends On

- P5 RC；可与 P6-T1 的打包工作并行，最终目录中必须包含这些资料。

### Not Included

- 外部反馈平台、云档、后台遥测、付费或账号服务。

## P6-T3 — 完成最终包冒烟、回滚演练与交接

状态：未开始。

### Outcome

项目获得一份经过目标浏览器检查、可以受控回退且不会丢档的发布交付，实际部署状态清楚。

### Scope

1. 固定最终包摘要，在四桌面浏览器和中端移动设备执行发布流程；Safari 使用真实浏览器。按空缓存/网络合同分别核验首屏、默认桌面新局可交易 p95 ≤ 10 秒初值及任意种子现场预热，不能把后者可取消当成默认开局达标。
2. 核验 P5 黄金命令流与最终构建的对应关系；任何改变经济/存档行为的差异返回 P5 复验。
3. 在独立存储副本中演练升级、保存、回滚及返回新版；旧版不兼容时拒绝而保留新档，兼容备份可恢复。
4. 从干净目录让接手者按说明启动、交易、备份，生成验收索引和交接记录，区分本地交付与公网部署状态。

### Acceptance

- 满足 P6-AC6、P6-AC7、P6-AC8；P6-AC1–AC5 的最终证据包含于索引。
- 不发生清档、重复本金/结算或未授权发布；未知公网 URL 不阻塞本地发布包交付。

### Depends On

- P6-T1、P6-T2。

### Not Included

- 在未指定托管服务上的实际部署；如以后得到目标输入，再按运行资料执行。
