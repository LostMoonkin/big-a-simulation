# P4 详细实施计划

状态：未开始。[Spec](./spec.md) · [Tasks](./tasks.md) · [阶段总览](../README.md)

## 进入条件与合同核对

1. P3 的规则与信息边界通过，四条玩法初筛已有可复盘证据；没有通过的路径先完成修正，不能用增加股票和文本掩盖。
2. P0 已冻结正式生成配额、名字/代码生成规则、24 模板清单与 6 链关系、两市市场 profile；P3 的 8 模板/2 链已有稳定 ID。
3. 已有核心快照、版本检查和 Worker 交互；本阶段增加产品存储和生涯体验，不能让 UI 直接读写核心内部余额或世界日期。
4. 确认 P1 数值协议在 200 股预期金额范围不溢出，IndexedDB 序列化形式不会把整分/整数股份转换成有损浮点数。
5. P0 已确定默认新局快速开局方案与启动计时协议；P4 落实该方案，不自行把完整静态快照定为唯一实现。

以下为拟实施目录：`packages/sim-core`、`apps/web`、`tools/sim-runner`、`tests/scenarios`。与总计划共享现有 API 及版本，不另建平行模拟器。

## 实施顺序与接口

### 1. 正式世界和发现机会（P4-T1）

- 按精确行业/规模矩阵生成两市各 100 股；分配 190 概念关联时同时满足每市标签数、成员总数、合法行业、至少两个行业及暴露和上限。
- 以初始化价格和股份回算市值档，不维护可独立漂移的第二份市值。稳定余数分配保持创始/流通/NPC 股份守恒。
- 用冻结虚构词库生成唯一名称与代码；对模板槽位和生成结果作重复、空缺及真实实体词表检查，并由人工抽查阅读自然性。
- 扩充 P3 子集到恰好 24 模板/6 链，保持原 ID 与历史含义；为每个分支准备能到达的场景，报告周期、链并发及 20 日预期更新仍受原规则约束。
- 完成市场筛选/排序、自选、公司详情、消息、组合、三类订单和回执的连通流；列表使用稳定股票 ID，不把当前行号当作选中对象。
- 展示 200 家错峰经营简报时按摘要合并，默认重要暂停只针对配置条件；信息聚合不丢弃完整公开历史。

### 2. 可恢复的开局与保存（P4-T2）

- 开局界面校验本金模式、范围与种子，按 P0 定案实现默认快速路径；任意非预置种子创建完整模型世界并显示 Worker 现场预热进度/取消状态。取消不提交半成品世界。
- 预热缓存键包含规则/内容/初始化配置/种子标识，值是完整世界检查点；玩家本金在恢复并完成入场转换后仅加入一次，重复提交创建请求不能重复发放。
- 若 P0 选择静态完整预热快照，校验其版本、种子和初始化参数，完整恢复钱包/目标/事件/随机状态，并与同输入重算比较；下载和恢复时间计入默认新局时长。版本不匹配不得悄悄使用旧快照。
- 分别埋点导航、开局控件可交互、默认配置确认和可接受合法交易命令；验收脚本在控件就绪后立即确认默认配置，计时包含下载、预热或快照恢复及入场，不混入人为阅读等待。
- 为 P5 提供固定网络、空缓存、每桌面浏览器至少 20 次默认启动的采样入口；目标为从导航到可交易 p95 ≤ 10 秒，首屏 UI 独立 p95 ≤ 3 秒。另测任意非预置种子 250 日现场预热，桌面 p95 ≤ 60 秒、移动 ≤ 180 秒；长预热可取消不抵消默认新局超时。
- 保存封套包含 `saveSchemaVersion/ruleVersion/contentVersion/careerId/worldTime/modelConfigHash/checkpointHash`；内部包含 RNG、账户记忆、目标相位、公开/隐藏事件、锁定与冻结、订单/计划、费用、保护状态和历史。
- UI 附属状态独立标识版本，至少保存自选、标注、暂停条件和必要视图选择；不会因此改变模拟随机流。
- Worker 只在已完成批次或核心确认的公开窗口暂停点导出快照，保存精确阶段与已发布事件标记；新闻暂停时保存不强制先清算，恢复后仍等待玩家指令且不再次公布/应用事件。存储层以 IndexedDB 事务写入不可变检查点及当前指针，保留上一有效检查点。
- 普通自动保存至少在日终完成的检查点执行，不为保存新增决策暂停；赛季结算、退休/耗尽确认后保存新状态，手动保存等待最近安全检查点。快进期间合并过时待写快照，不允许旧写入完成后覆盖较新的指针。
- 导入采用“解析/校验→兼容性判断→在临时核心恢复并校验→建立新存档记录→用户切换”的流程；默认不覆盖当前生涯。没有已测试迁移器时拒绝不兼容版本。
- 处理浏览器存储不可用、事务中断、配额不足和文件损坏：维持当前内存与旧有效档，显示未保存状态，提供重试/导出。世界不因错误自动推进或重新创建。

### 3. 赛季和生涯闭环（P4-T3）

- 使用原始入场日/本金生成生涯记录，按照精确规则计算赛季编号及当季日序；NPC 和世界排程继续使用世界时钟。
- 日终依次完成清算、到期释放、日线/里程碑/耗尽统计，再按 `careerId+seasonNo` 生成唯一只读成绩并停在结算点。
- 结算页展示期初/期末净值、现金、收益、最大回撤、累计倍数和同区间虚构指数；零分母显示不可用，账面净值不转现金。
- 继续仅解除结算暂停，下一世界日再正常解锁股份/收费/发布；计划到期使用绝对时点，不因新季再次冻结或重报总量。
- 退休与确认资本耗尽是独立终止指令；关闭标签页只是退出。终止后保留可阅读和导出的最终记录，不再接受推进或交易指令。
- 现金里程碑包括仍属于账户的冻结现金，不包括未卖出股票或累计卖出额；各倍数连续天数、已达成标记及耗尽天数跨季延续。
- 当第 250 日同时触发里程碑/耗尽条件时，按同一日终快照更新再呈现结果，反复打开页面不重复生成记录。

### 4. 历史归档与长局交付（P4-T4）

- 日线完整保留；小时线保留至少最近 120 日。归档前提取所有运行信号依赖、有效形态的冻结水平/确认时点和标注锚点，不从 UI 当前可见切片重算策略状态。
- 标注以股票、尺度、连续世界时点与价格锚定；归档区间保留元数据并标为历史未展开，不把图形平移到最接近的仍存 K 线。
- 提供有/无归档两条运行路径的同种子对照；后续公开信号、NPC 决策及市场状态一致，形态记录不因裁剪重开。
- 预登记至少 3 个技术长局种子，完整运行“250 日预热＋1,000 玩家日”；分别在内存持续运行及每季保存/重启恢复，两路使用相同交易与赛季继续指令，对比 250/500/750/1,000 日与后续批次。
- 必须包括第 240 日附近公开、260 日后公布结果的事件链，以及跨季计划和甲市场新买锁定股；若等待超过 20 日，链须按原规则更新预期，不能借跨季绕过到期规则。
- 打包可本地启动的 Alpha 静态构建、启动说明、存档兼容性及失败恢复说明，生成逐项证据。全面自然经济样本和性能优化由 P5 执行，此处不冒称已完成。

## 状态和主要 UI 流

| 流程 | 正常转移 | 错误/重复操作处理 |
|---|---|---|
| 开局 | 参数校验→P0 默认快速路径或任意种子现场预热→一次入场→首个决策点 | 配额/版本失败保持开局页，取消无半成品档；首屏不冒充可交易 |
| 交易 | 市场/自选→公司/消息→订单→回执/持仓 | 资源或持有期拒绝给明确原因，不修改余额 |
| 保存 | 安全决策点检查点→事务写入→成功时间/版本更新 | 失败保持旧档；重试不重放交易或公告 |
| 导入 | 选择文件→验证→新存档记录→切换读取 | 不兼容/损坏不替换当前生涯 |
| 赛季 | 日终唯一成绩→暂停/保存状态→继续或退休 | 重开只读成绩不推进日期、不重复结算 |
| 耗尽/退休 | 已满足条件后确认，或主动退休→最终记录 | 低现金不代替耗尽；普通关闭不执行终止指令 |

自动保存失败时显示最后成功时点和当前未保存状态，保留会话与导出入口；不能显示虚假的“已保存”。在赛季停点失败不重新结算，重试只重写同一检查点。操作界面是否继续由明确的玩家指令决定，系统不得在存储错误后自行快进。

## 验证流程与证据

计划入口为 `npm run verify:p4 -- --out artifacts/verification/p4/<run-id>`；批量入口使用 `npm run sim:batch -- --manifest <manifest> --out <dir>`。这些命令在实施时提供，目前文档不代表命令已存在。

每次证据目录包含：

- `manifest.json`：规则/内容/保存版本、源码 hash 或 commit、参数与种子清单 hash、环境、预热/玩家日数、执行命令。
- `results.json`、`summary.md`：沿用总实施计划的场景状态、度量、失败/缺失项与阶段结论，索引本阶段各专项报告。
- `acceptance.json`、`regression-report.json`：P4-AC1–10、A18/A25–A28/A32、P1–P3 回归结果及失败原因。
- `world-content-report.json`：全部公司配额、190 关联、合法暴露、唯一虚构名称、24 模板/6 链及分支运行结果。
- `save-roundtrip-report.json`：同指令恢复、旧档保留、事务中断、配额不足、损坏/版本拒绝和成功迁移（若实现）结果。
- `startup-report.json`：P0 所选默认方案、默认/任意种子计时点、缓存/静态快照与重算一致性、初步测量及 P5 待签收项目；不得用现场长预热替代默认启动结果。
- `career-report.json`：季末唯一键、三次跨季边界、锁定/计划/事件延续、现金里程碑与耗尽条件。
- `history-longrun-report.json`：归档等价、3 个技术种子的连续/恢复摘要及不变量；与 P5 的经济平衡报告明确分开。
- `demo.md` 和构建位置/校验值：操作步骤、可复现存档、预期画面、已知限制及阶段结论。

先跑生成/内容静态检查与固定边界，再跑存储故障注入、跨季和归档场景，最后跑长局与端到端操作。账务、信息或恢复错误未清零时不生成“通过”的 Alpha 验收结论。

## 现场演示脚本

1. 以固定本金和自选本金各建一局，展示默认快速路径与任意种子现场预热的区别、首屏和可交易两个时点，以及完整重算/缓存/采用的静态快照一致；筛选两市、添加自选、打开关联消息，在公司页完成三种订单及部分成交回执。
2. 在含锁定股、未完成计划和未公布事件的暂停点保存，关闭再打开，核对标注/自选、目标/资源和下一批成交；导出并导入为独立存档复现。
3. 注入一次保存失败，展示旧检查点仍可用和未保存提示；尝试损坏/不兼容档，当前世界保持不变。
4. 从第 249 日演示到第 250 日结算，重复打开成绩页，再继续到第 252 日；展示锁定股解锁、跨季计划和连续里程碑判定。
5. 演示跨季长事件在原日期公布，以及退休、资本耗尽确认与普通退出的区别；出示第 1,000 日技术报告和小时归档前后等价结果。

## 失败处理与退出标准

- 生成失败明确记录种子和配置，修正约束求解或合法配额；不得降低规则以悄悄返回“差不多 200 股”。
- 存档失败保留旧档/内存并输出可复现信息；无法验证兼容的文件只拒绝，不猜测迁移后进入交易。
- 跨季状态不一致从首次差异批次定位，禁止清空目标、订单或事件以使测试通过。
- 长局出现全市场流动性枯竭时移交 P3/P5 模型分析并记录阻塞，不能在存储优化中添加现金补偿。
- 全部 P4 AC 通过后进入 P5。Alpha 功能完成与发布验证未完成须同时在交付说明中体现。
