# P5 实施计划 — 验证、平衡与性能

状态：未开始。验收合同见 [spec](./spec.md)，执行切片见 [tasks](./tasks.md)。

## 进入条件与约束

1. P4 的 200 股 Alpha 可完成 250 日赛季、继续、保存/恢复、导入/导出；P1–P4 对应规则检查已通过。
2. P0 已关闭双市场特色、价格保护、确定性数值协议、40 股配额、依赖版本、默认新局种子/完整预热快照方案及基准设备；P3 的差异模型已实现，不能在 P5 临时填补核心设计。
3. 读取 [验证方案](../../docs/design/model-validation.md)、[规则](../../docs/design/market-model-rules.md)、[引擎研究](../../docs/research/engine-feasibility.md)，以当前版本冻结场景含义。A13/A14 如因 P0 价格保护决策更新，保留 ID 并记录前后差异。
4. 规划路径 `packages/sim-core`、`apps/web`、`tools/sim-runner`、`tests/scenarios`、`artifacts/verification/p5/<run-id>` 尚未存在；由前序阶段建立实现路径，本阶段产生实际证据。此处没有可直接运行的 npm 命令。

## 实施顺序与成果

### 1. 建立一次可复核的候选运行

- 为当前构建写运行清单：源版本、构建摘要、规则/内容/存档版本、设备/浏览器/OS、种子列表及用途、参数、策略版本、外生流键、起止时点与预热天数。
- 模拟运行入口接受场景、种子、参数、策略、玩家日上限和诊断开关；返回退出状态、违规计数、逐日指标及失败时的命令日志/最小可复现快照。
- 按主体、用途、时点固定随机流，允许不同比较策略改变订单和价格，而不改变外生事件。比较器在相同世界时点核验权威状态摘要，排除运行耗时、UI 选择和诊断日志等非经济字段。
- 先重跑 A01–A32 和 P0/P3 新增的双市场合同；对存档损坏、字段越界、超额文件、非法命令用有限明确的输入夹具，验证原状态不受损。
- 输出 `manifest.json`、`rules-report.md`、`replay-comparison.json` 与 `failures/`。故障要能从命令序列重现，不只保留一张图。

前序阶段及本阶段应提供以下未来命令接口；当前写出的是交付合同，不是可执行状态：

```text
npm run verify:p5 -- --out artifacts/verification/p5/<run-id>
npm run sim:batch -- --manifest <manifest> --out <dir>
npm run benchmark -- --profile <profile> --out <dir>
```

### 2. 长局经济、策略与对抗检查

| 运行组 | 规模与行为 | 样本 | 时长与用途 |
|---|---|---|---|
| 基准存续 | 两市各 20 股，仅公开经营、价值、库存再平衡与噪声 | 固定 100 种子，其中预先选 10 个 | 全部预热 250 日＋玩家 250 日；所选 10 个延长至玩家 1,000 日 |
| 全量存续 | 两市各 100 股，全行为、事件及两市差异 | 固定 100 种子，其中预先选 10 个 | 同上；延長前不按收益/流动性结果挑选 |
| 调参 | 200 股全行为 | 30 个训练种子 | 预热 250 日＋玩家 120 日 |
| 初筛 | 200 股全行为 | 另 30 个保留种子 | 预热 250 日＋玩家 120 日 |
| 扩展确认 | 200 股全行为 | 100 个保留种子 | 预热 250 日＋玩家 250 日 |

同一完整运行若同时满足两项协议，可复用其证据并声明，不必重复消耗；前提是参数、策略、数据和种子身份完全匹配。存续组不得用于挑选保留策略；任何据结果调参的保留组整体退役为训练用途，重新登记尚未观察的新组。

- 先关闭复杂事件，逐种子、逐市场定位成交覆盖、无交叉与价格保护阻断、现金集中与库存耗尽。40 股基准逐个世界/市场执行 P0 固定的 90% 股票×80% 成交日出口，未达需修复或回 P0 明确修订口径后完整重跑；不能仅解释放行。200 股全行为按常态、危机等环境分组诊断，不对真实危机机械套用零突发事件基准，但不接受未解释的长期全市场停转。两者均不得用总体均值掩盖单一世界问题，不补造现金/成交。
- 再验证四路径各两成立、两失败的预登记场景。执行策略固定目标数量、期限和未完成量代价，报告成本—完成率；不能用仅成交便宜部分的策略冒充更优执行。
- 基准包括持币、分散持有、风险/换手匹配随机交易、价值、预期差、短线/波段趋势、突破/回踩和主题轮动。不得用未来峰谷、实际未公开经营或隐藏 NPC 钱包选股。
- 技术定义直接复用验证方案 4.1，不另起相近算法。统计样本不足、识别延迟、后续五窗口、退出完成率；拐点同时保存发生时点与 `confirmedAt`，决策最早为后者之后的可操作批次。
- 完成六类消融：公开消息、概念成员、资金约束、T+1、多周期/技术信号、离线收益顺序。约束消融是明确标识的非游戏对照；离线打乱只查识别和泄露，不能声称具有可成交收益。
- 对抗覆盖小单抬末价、概念刷量、同价拆单、撤单双解冻、提前花卖款、拉 A 卖 B、手续费周期、扩带触发、读档重抽。先做静态经营控制，再做完整模型；资金/库存用尽就是实验结果，不补满继续循环。
- 运行跨季第 240 日附近启动、第 260 日以后揭晓的事件链，以及跨季委托、持仓解锁、连续五日里程碑和第 1,000 日结算。日历、事件、目标相位和随机键连续。
- 输出 `economy-report.md`、`strategy-report.md`、`shape-report.md`、`ablation-report.md`、`adversarial-report.md`，附原始汇总 CSV/JSON、样本区间和异常种子。

### 3. 浏览器、响应与资源预算

P0 先登记一台桌面基准设备与一台中端移动设备：具体型号、CPU、RAM、OS、浏览器、供电/节能状态。P5 执行前复核并冻结版本，保留四桌面浏览器的真实机器记录；Safari 使用 macOS Safari，移动端优先补 iOS Safari。设备未具备时如实标待测，不用自动化引擎冒名通过。

使用发布构建、本地或同一静态预览服务、相同 200 股完整状态和固定命令。关闭开发工具参与性能计时；记录空闲后台及电源状态。所有耗时区分主线程响应、Worker 计算和磁盘/序列化，避免把加载图表当成世界恢复。分位数方法随 profile 固定；仅 5 次的预热/恢复样本同时报告全部原始值及最大值，不能声称得到稳定的总体尾部估计。

P0 在优化前固定首次访问网络 profile、缓存清理范围、默认种子选择及静态分发方案；P5 严格重用并记录。初始网络候选为下行 20 Mbps、上行 5 Mbps、往返 80 ms、无额外丢包，最终数值由 P0 按目标用户条件定案。冷启动清空该站点的 HTTP/应用初始化缓存与 IndexedDB，用发布包加该网络条件测量，不把本机已缓存下载计为首次访问。默认种子可以从静态随包分发的完整预热快照集合选择，也可以现场计算；不得新增后端依赖。快照必须匹配规则/内容版本、种子和初始化参数，包含钱包、股份、目标、事件、历史与随机流，并能与完整重算逐项一致；默认选择规则及快照覆盖范围不能对玩家谎称每次都是未缓存的任意种子。

“首屏 UI 就绪”止于开局控件可交互，不等于能交易。“默认新局可交易”从导航开始计时，脚本在开局控件就绪后立即确认默认配置，止于世界预热/恢复及一次性本金注入完成、可接受合法交易命令；不包含人为阅读等待，但包含下载、默认快照和初始化耗时。每个桌面浏览器做至少 20 次空缓存默认启动，记录两个独立时点与原始样本。任意自定义种子的首次现场预热是另一条高级开局路径，单独报告 60/180 秒预算；进度和取消做得好也不能抵消默认开局迟迟不可交易。

以下是新增的待测工程预算，P0/P5 开跑前登记；不是已有测量结果。因实际设备证据调整时记录原因、旧目标和新目标，不得测完后无说明改成“通过”。

| 指标 | 执行协议 | 初始目标 |
|---|---|---|
| 首屏 UI 就绪 | 上述空缓存网络协议，20 次导航到开局控件可交互；不把进度骨架误记为交易就绪 | 桌面 p95 ≤ 3 s；移动技术检查记录实测及限度 |
| 默认新局可交易 | 同 20 次默认启动，从导航到可接受交易命令；含静态快照下载或默认现场预热 | 桌面 p95 ≤ 10 s；移动单列，不据此承诺完整手机 UX |
| 单日推进 | 5 次热身后，3 个世界各测连续 100 日；普通日与事件密集日分开，含完整核心更新 | 桌面普通日 p95 ≤ 200 ms；事件密集日单列；移动 p95 ≤ 1,000 ms |
| 任意自定义种子首次 250 日现场预热 | 清除此版本初始化缓存，预先固定 5 个未预置快照种子；从确认参数到世界可交易，记录耗时、进度和取消 | 桌面 p95 ≤ 60 s，移动 ≤ 180 s；可见进度间隔 ≤ 1 s；不能用此预算放宽默认新局目标 |
| 完整预热缓存恢复 | 5 次重启，缓存须含钱包、目标、事件、随机流及指标；与重算状态摘要相同 | 桌面 p95 ≤ 3 s，移动 ≤ 8 s |
| 可见交互 | 图表/列表选择、下单反馈各至少 30 次；模拟繁忙时重复 | 主线程反馈 p95 ≤ 100 ms 桌面、≤ 200 ms 移动 |
| 取消快进 | 在预热、事件密集期和跨季前各 10 次，按批次安全点停止 | 桌面 p95 ≤ 250 ms，移动 ≤ 1 s；不得多走一整个未请求赛季 |
| 保存与恢复 | 第 250/500/1,000 日完整世界，各 5 次；恢复后继续并比对 | 桌面 p95 ≤ 3 s，移动 ≤ 8 s；成功提示只在事务完成后出现 |
| 长局内存 | 玩家日 1/250/500/750/1,000 同一静止点采样，含 UI/Worker；记录可用测量口径 | 桌面峰值目标 ≤ 512 MiB、移动 ≤ 256 MiB；可丢弃缓存不得随已归档小时/批次无限增长 |

内存还应报告数据结构计数和存档字节数，以区别日线合法增长与泄漏。某浏览器无法分离 Worker 堆时报告进程增量/上界及测量局限，不能把主线程堆当作总内存；预算超标先查增长来源。下载体积单列应用资源与默认完整快照；其预算由 P0 冻结、P2 测量校准，首屏/可交易时长仍按上表各自判定，不能相互替代。

四桌面浏览器均走新局→消息→交易→快进取消→跨季→导出→新会话导入→继续，使用黄金命令流核验 P0 规定的跨浏览器确定性。移动设备走缩小技术检查，不宣称完成手机 UX。存储配额不足、事务中断、坏校验/非法状态导入与不支持版本均需保留上一份有效档和明确恢复入口。

输出 `performance-report.md`、`browser-matrix.md`、`storage-reliability.md`，附测量脚本/步骤、原始数据和机器标识；不得预填任何“通过”结果。

### 4. 目标玩家试玩与 RC 封版

- 招募 6–8 名偏策略经营且愿意做部分短线操作的玩家，每人 30–45 分钟；给一份经营场景与一份小时级场景，角色/先后顺序交替。
- 不在测试开始就解释正确买卖答案；记录其公开证据、反证、部分成交、新旧仓、周期切换、暂停等待和结算理解。
- 分母为实际完成该项的总参与者，同时报告退出/未完成者，不能删掉不理解的玩家抬高比例；达到 ceil(2n/3) 的规则解释目标及多数周期取舍目标。
- 若失败先改信息、回执或行为反馈，保留交易合同；修改机制则回到对应 P0/P3 设计、重跑受影响规则和新保留集。必要时再招募同目标群体验，不能用已训练原参与者单独证明首次理解改善。
- 汇总 G0–G4、全部 AC、告警处置和未解决问题，固定 RC 版本及包摘要。轻微已知问题可有明确适用条件和恢复办法；正确性、数据损坏、核心流程和未解释长期停转问题阻塞 RC。

## 演示与证据归档

以一个已登记世界演示“大单部分成交→小时/日切换→公开事件→跨季继续→保存恢复”，展示同世界回放摘要与一次有理由的失败交易；报告页能定位全部 A01–A32 和 G0–G4。
证据根目录为规划的 `artifacts/verification/p5/<run-id>/`，生成总计划要求的 `manifest.json`、`results.json`、`summary.md`；根索引 `index.md` 关联各报告、原始数据、复现步骤及 RC 摘要。自动化检查退出码失败时不得生成已通过状态；结果字段使用 pass/fail/not_run，告警另记 severity 和处置，不能将缺少必需证据算作通过。

## 失败处理与后续

- 账务/信息/确定性问题：保留最小复现，修复源头并加入回归，重跑相关长局；不进入 P6。
- 经济/形态告警：定位资金、目标、信息或保护规则，记录原因和取舍。40 股基准未达固定出口，须修复或回 P0 修订并完整重跑；200 股全行为按环境诊断，影响四条路径或出现未解释长期停转则必须修复，不能仅修改阈值。
- 性能问题：先剖析排序、历史扫描、消息复制、图表和存档；保持每股同逻辑与所有账户资源检查。只重跑受影响协议，避免无依据全量反复调参。
- RC 对外仍称模拟策略游戏，不把回测结果写成金融有效性证据。P6 接收构建、版本清单、全部验证索引与已知问题，无需新增逐阶段人工批准流程。
