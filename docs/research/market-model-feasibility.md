# 虚构金融市场模拟：市场模型可行性研究

> 0.2 设计同步：26 个 NPC 已细分观察尺度与目标复核节奏，新增波段/长期价格信号；预热 250 日，每 250 玩家日只结算成绩并可跨季继续。技术形态从成交历史识别，不设置波浪价格剧本。实施以[主设计与规则](../design/gameplay-market-model.md)为准，尚未完成行为模拟验证。

> 2026-10-01 范围更新：首版已调整为每市场 100 股、两市共 200 股；每市场 6 个行业、世界共享 8 个概念，每股 0–2 个概念标签。当前模型选择为“有限预算异质资金群体＋每子步统一价批量竞价”；新闻先公开，玩家与 NPC 依据同一公开信息撤改委托，然后本批统一清算，事件暂停发生在清算前。具体撮合、新闻时序和参数以[玩法驱动市场模型设计](../design/gameplay-market-model.md)为准；本文保留可行性研究背景，不替代详细设计。

核验日期：2026-10-01。定位：单人 Web 策略经营游戏，判断环境、选股、调仓并逐步做大资金，同时支持短线与资金博弈；首版两个虚构股票市场、各 100 家公司。本文中的现实制度为研究参照；其余带有“建议”的内容均为尚未经过原型验证的设计判断。

## 结论

可行。首版优先采用“日级决策与事件暂停 + 内部细步进 + 有预算、有库存的聚合对手盘”。日 K 只是展示粒度，不会妨碍真实的买卖数量约束；必须避免的是直接拿整根日 K 的高低点来判断订单成交。小时 K 可以用于展开查看，但不必每小时强迫玩家暂停。

200 家公司的数量不是最难的问题。真正困难的是同时做到：走势有可理解的因果、噪声不会淹没策略、玩家资金能改变成交和价格、玩家又不能通过自己的冲击凭空刷钱。这部分应先用 40 家股票（两市各 20）的无界面模拟器验证，再扩展到 200 家；该模拟器是同规模可玩原型的底层先行验证。

首版建议统一虚构交易窗口和货币单位，保留两个市场的制度与投资者结构差异；真实时区、节假日、夏令时、汇率与清算细节以后独立扩展。它们对当前“策略经营”体验的价值，低于事件与资金容量。

## 现实规则核验与虚构映射边界

| --- | --- | --- |

| A 股交易时段 | 现行上交所规则区分开盘集合竞价、上午/下午连续竞价及收盘集合竞价。 | 不照搬时钟：保留开盘、盘中、收盘的阶段；内部每子步统一价批量竞价。 |
| 美股当日可卖 | SEC 投资者公告明确举例：以账户已有现金足额买入股票，可以当天卖出；用尚未结算的卖出款购买另一证券又当天卖出，则会触及资金支付限制。 | “乙市场”：买入即可卖出、允许资金在游戏内重复使用；明确为游戏简化账户，不能称为完整美股现金账户。 |
| 美股结算 | 大多数相关证券交易自 2024-05-28 起采用 T+1 标准结算。“T+1 结算”与“当日能否卖出”是不同问题。 | 首版账务可成交即转移并略去现实交收过程，制度提示只写“当日可卖”；以后若增加结算，应另设可用现金、应收款与可售批次。 |
| 美股日内保证金 | FINRA 2026 新规则替代旧日内交易要求，生效日为 2026-06-04，券商可过渡至 2027-10-20；旧 PDT 与 25,000 美元门槛不能当作永久统一规则。 | 首版没有融资，不实现 PDT 或保证金制度。 |
| 美股交易时段 | NYSE 核心时段为美国东部时间 9:30–16:00。扩展时段与不同场所有额外差异。 | 乙市场与甲市场使用统一虚构日历及交易窗口，首版不复刻实际跨时区。 |

## 时间模型：把“观察”“决策”“成交”分开

| 方案 | 优点 | 主要代价 | 结论 |
| --- | --- | --- | --- |
| 单根日 K 直接结算 | 开发最省、推进快 | 不知道最高最低出现顺序；无法可信地处理同日反复交易、部分成交和事件中断 | 不采用 |
| 每小时强制停一次 | 同日调整显著 | 双市场导致操作次数膨胀，玩家易沦为点下一回合 | 作为可选节奏 |
| 日决策 + 事件暂停，内部细分 | 兼顾经营节奏与成交约束 | 需要时间队列和可回放订单状态 | 推荐 |

建议一个虚构交易日定义为 4 个交易小时，内部先用 16 个执行子步；这是游戏时间，不宣称等同现实交易所时钟。显示层提供日 K，以及由 4 个子步合成的小时 K。两市场可以同时开市，差异由交易制度与资金行为体现。

默认日循环：盘前环境/消息与持仓检查 → 提交目标仓位、限价或分批计划 → 推进执行 → 重要事件/风险阈值可暂停 → 收盘复盘。自动暂停是玩家的通知策略。突发消息先公开，在尚未清算的本批暂停，玩家与 NPC 基于同一公开信息撤改报价后统一清算；不让 NPC 先成交跳价，也不承诺按旧价成交。预告事件只预告时间，不透露结果。

当天买入锁定和当日可卖的差异，仍可通过事件中断、预设退出条件或手动展开时段体现。若玩家永远只在收盘后操作一次、又没有任何日内订单，则两者体验确实会接近，不能仅靠一个 T+0 标签制造差异。

短线模式须是完整玩法：玩家可以在已经完成的小时 K 后主动停下，检查上一批结果与当时公开消息，再把订单提交给下一执行子步；可以连续观察四个时段，也可以切回日级经营。事件仍可在小时内部打断。甲市场允许卖出昨日持仓、买入新仓，但新买仓位要承担隔夜风险；乙市场允许当天反复进出，仍支付费用并承担批间价格变化和冲击。首版无需逐笔行情、高频抢单和逐秒操控。

快进到明日/下周要运行同一批内部子步，只少做画面渲染。不能在快进时换一套价格算法、跳过订单/结算或吞掉指定暂停事件。保存当前时间、随机流、订单队列和批次锁定状态，保证相同种子及相同行为可重放。

未来若加入跨时区：一个全局时间轴，各市场各自 sessionId 和 businessDate；T+1 按该市场下一交易日解锁，而非经过 24 小时。新闻有统一发布时间，不因切换市场界面获得未来信息；闭市市场通过下一次开盘承接消息。跨市场转换资金还需 FX 报价、结算日历和资金转移时滞。这应作为独立扩展，不混入首版。

## 公司与行情：生成经济属性，不生成独立随机曲线

每家公司先生成稳定的“身份”：主营行业、0–2 个概念标签（须有业务暴露依据）、规模档位、总股本、流通比例、资产负债、利润率、成长性、经营质量，以及对利率、投入成本、出口需求等虚构因子的暴露。行业应稳定；概念可以兴衰、加入或退出。市值 = 成交参考价格 × 总股本，流通市值单独计算，不能把市值当成公司现金。

每市场 100 股、6 个行业，世界共享 8 个概念。按统一的六行业顺序，甲市场行业配额为 24/20/18/16/12/10，乙市场为 10/16/12/18/20/24；每市场初始大盘 20、中盘 35、小盘 45。生成器同时约束行业、规模与概念业务暴露，不能把每市场 100 次抽签当成彼此独立。两个市场通过权重和制度区别：例如甲更受主题、政策与散户预期影响，乙更受盈利、全球流动性与机构调仓影响，但这些是虚构设定而不是现实市场的绝对结论。

推荐四层驱动：

1. **经济状态**：虚构利率、需求、信贷、成本和风险偏好，以有持续时间的状态变化演进。
2. **行业/概念传导**：同一事件对上游、下游、替代品可以异号；冲击有滞后与衰减。
3. **公司经营**：收入、成本、债务与现金影响长期估值区间；财报发布改变市场对它的认识。
4. **预期与交易**：NPC 对估值、趋势和新闻有不同判断；噪声改变其预期和下单，不直接把成交价格强制改成随机数。

可以维护隐含的经营价值锚与 NPC 的主观估值，但公开价格最终来自撮合。没有成交的子步显示延续参考价与零成交量，不能伪造价格变动、成交量或最高最低。公司价值锚也不等于玩家可无成本成交的“真实价格”。

避免每条消息直接规定“上涨 5%”。消息调整经营变量、预期、分歧、流动性和风险预算，结果再受原有估值、拥挤程度和资金约束影响，才能出现利好兑现、错误传闻反转和板块轮动。

事件记录至少区分：真实状态、发布时间、可见信息、影响渠道、持续期、预期程度和后续分支。生产核心应使用可校验模板与数值规则；无需依赖实时 LLM 来决定价格、数值或叙事真实性。

## 首版对手盘：有限资金的聚合投资者 + 统一价批量竞价

不建议给每家公司模拟数千个独立投资者。原研究曾考虑每市场约 12–20 个聚合账户；当前账户数、资金类型与权重以详细设计为准。一个账户持有多只股票，共享现金和风险预算，具体参数仍需性能与行为验证。

每只股票从这些账户生成少量真实有资金/库存支撑的买卖委托，可以使用多个限价表达意愿；本批统一选择清算价并分配数量。当前选择替代了前轮多档连续撮合，保留有限容量而不以提交顺序赋予速度优势。甲市场的做市只是内部供需模型，不冒充现实 A 股普遍存在指定做市商制度。

每个子步按以下顺序执行：

1. 推进全局时钟、解锁到期批次、处理到期委托与公司行为。
2. 公开本时点消息；事件暂停发生在本批清算前，让玩家有机会依据该公开信息撤改委托。
3. 玩家与 NPC 基于同一公开信息形成本批决策，各 NPC 不读取玩家本批订单再临时修改观点。全账户统一冻结现金和可售股份，不能每只股票复制一次现金。
4. 汇总本批有效订单，以统一价格批量清算；没有可相容的买卖供给则不成交，库存不足则部分成交。清算价与数量分配按详细设计，不用提交毫秒先后决定同价优势。
5. 成交同时转移买卖双方股份和现金、计费；记录统一成交价、数量与双方身份。成交量按一笔成交计算一次，不能把买卖两侧加总为两笔。
6. 未成交部分进入下一子步或依时效撤单；只有取消成功后才释放预留。甲市场新买批次保持锁定，乙市场新买股份可在下一批参与卖出。
7. 每批实际成交生成一个价格点和成交量，再合成小时 K 与日 K；更新 NPC 库存、损益、持仓偏好和风险预算。

首版订单可以只支持：带保护价的即时单、限价日单、目标仓位分批计划。市价单在深度耗尽时部分成交/剩余撤销，不能用下一根 K 线收盘价补齐。限价单“价格碰到过”不代表一定成交，还要有本批对手数量与清算分配；当批以外的历史价格不构成成交资格。

为控制工程量，不必重建现实交易所全部订单类型、隐藏单、做市细节与真实清算机构；但需要把账本、撮合、规则和时间调度作为彼此独立模块。

### 必须成立的账务不变量

- 无融资首版中，任何账户的可用现金、预留现金、可售股份与锁定股份均不得为负。
- 每次成交买方扣款 = 卖方入账 + 明示费用；费用进入费用账户。
- 每只股票的总股份在投资者/公司回购账户之间转移，除明确增发、拆并股、注销等公司行为外不凭空变化。
- 市场交易本身不创造现金。分红由公司现金付出，税费进入指定账户；外部注资/撤资必须有明确经济事件与对侧账目。NPC 不能每子步免费补满钱包与库存。
- 浮动市值无需守恒：股票涨价会增加估值总额，并不代表系统应发行同等现金。
- 现金使用最小货币单位整数或受控定点数；每笔费用与价格舍入规则固定。股票拆并股另有碎股处理规则。

## 玩家体量：容量约束是成长玩法的一部分

### 短线与资金博弈的可观察信息

短线玩家应能判断“谁急、哪里拥挤、成交容量够不够”，而非只猜随机 K 线。首版提供以下观测，但不把隐藏参数或未来事件直接暴露给玩家：

| 可见信号 | 能支持的决策 | 保留的不确定性 |
| --- | --- | --- |
| 已完成小时 K、实际成交量与换手 | 判断相对以往是否放量、是否快速消耗流通筹码 | 放量不保证继续上涨，卖方也可能在退出 |
| 上一批申报失衡、近期成交比例与容量估计 | 选择限价、分批进出或放弃追价 | 当前批隐藏订单不公开，估计容量不是承诺 |
| 主题热度、涨跌扩散、龙头与跟随股表现 | 判断热点扩散、拥挤与轮动 | 热度是已发生的信息，主题可能透支 |
| 上一批买卖未成交数量与申报失衡 | 估计哪方需求较难满足 | 统一价竞价没有天然主动方，申报数量也不是现金净流入 |
| 上一时段汇总的资金风格参与估计 | 区分短线追随、长期吸收与流动性供给 | 延迟、带误差、不可显示所有 NPC 的真实持仓与明日订单 |
| 消息来源可信度、预告时间与分歧 | 判断是否在交易惊喜、预期兑现或传闻 | 同一消息在不同估值与持仓结构下可能不同方向 |

可以形成几类有取舍的策略：甲市场先买承担隔夜锁仓风险、持有旧仓参与冲高兑现；乙市场日内试错与退出更灵活但周转成本更高；小盘主题弹性高而退出难，大盘容量高但短线价格弹性较低。机会必须与波动、成本和反转风险同时存在，不提供跨所有种子稳定生效的万能赚钱指标。

这里的“多空双方”首先指愿意买入的现金预算与愿意卖出的持股库存；看空可以减仓或拒绝接盘。首版没有裸卖空。若未来允许真正卖空，必须补上借券库存、借券费用、保证金、召回和强平，不能直接把持股变成任意负数。

### 资金做大后的玩法变化

玩家的影响应来自订单相对当时市场深度与可成交量，而不是总资产达到某阈值就让全市场上涨。相同 1,000 万的买单，对深度很大的公司和冷门小股应有不同结果。

第一层是**直接冲击**：大买单改变本批供需交点，可能提高统一清算价或只能部分成交；大卖单反之。第二层是**后续反应**：NPC 库存与现金改变报价，趋势账户可能跟随，基本面账户可能反向提供供给。第三层是**组合传导**：机构减持其他股票筹款、行业资金拥挤度变化；先使用有限、滞后的传导，避免一只小股带动全部股票。

市场指数从成份股价格和权重计算，玩家改变大权重股票自然影响指数；不要另设“玩家资产足够大就额外给指数加点”的重复影响。首版不必实现玩家直接影响宏观经济或央行政策。

资产展示同时给“账面净值”和“预计按正常成交能力退出所需时间/费用”。最终胜利不能只认最后一笔极小成交推高的全仓市值；可用持续若干交易日的净值阈值并结合可实现资产价值，以防用自身冲击刷富可敌国结局。

初始资金允许自定义，但应拆为标准挑战档和沙盒范围。标准挑战档以相对典型股票日成交额的比例校准，确保起步还有成长空间；极高资金直接进入大资金容量玩法，单独记录种子与起始资产，避免与小额开局的绝对财富成绩混比。

## 容易破坏经济系统的漏洞与验证

市场冲击函数不能任意拼接。Gatheral 的原始研究说明冲击形状与衰减之间存在无动态套利约束；因此“平方根涨价 + 随意指数回落”不能被直接宣称安全。[Gatheral, No-Dynamic-Arbitrage and Market Impact](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=1292353)。本方案首先依靠有限账本与真实报价减少漏洞，但不声称已经证明无操纵或自动保证平衡。

| 漏洞 | 必须验证的行为 |
| --- | --- |
| 买一笔推高价格，按新中间价无限卖出 | 固定消息/基本面、禁止 NPC 趋势响应时，买卖往返不能靠系统自我标价稳定产生正收益；卖出仍受下一批有限供需和统一清算价约束。 |
| 拆成很多小单，重置每单深度 | 同一子步共享同一批有限报价，不能拆单后凭空得到更多容量或同价分配优势；若分时间交易更好，应来自下一批真实报价变化。 |
| 小股拉高 → 板块指数被抬 → 卖出其他持仓 | 跨股票影响要有资金约束、权重与延迟；对跨资产循环路径做压力测试。 |
| 买后撤单恢复现金两次、重复回放重复成交 | 订单状态机只接受一次有效状态转移；保存/读取不重复记账。 |
| 看到当天高低价再按最有利时点买卖 | 订单到达时间后才有资格匹配；历史完整 K 线不能参与当前撮合。 |
| 跳过到明天规避锁仓，或按另一市场日期解锁 | 锁仓依据市场的交易日 ID；快进和手动逐步结果一致。 |
| 每次打开界面/读档重新抽事件 | 随机源按世界、事件、市场和主体分流；同种子同操作稳定重放。离线单人无法真正阻止玩家读源代码和改档，竞争排行榜应另做可信验证。 |
| 空仓永远不败或长线永远指数增长 | 破产/退休/期末结算规则与市场生成器一起验证；没有负债时，接近零资产不等于法律意义破产。 |

测试层次建议：先跑账务与订单边界用例，再跑固定种子的多年度批量模拟，最后让随机交易、持有、分散、追涨、新闻响应和操纵策略同时参与。测试指标包括负余额/股份违规次数、成交比例、换手、冲击、破产分布、行业相关性、事件解释率和玩法差异。复杂市场不必与现实每个统计量吻合，但不能让一种利用实现漏洞的策略统治所有种子。

对 200 家股票和 16 子步，每游戏日是约 3,200 次股票状态更新；这只是循环规模估算，不是浏览器性能结论。每个子步的投资者数量、排序、历史数据存储和长时间快进仍要基准测试；以无需渲染的纯模拟核做验证，再测桌面与移动浏览器。

## 对开发复杂度的影响

| 工作包 | 难度 | 首个可验证结果 |
| --- | --- | --- |
| 原创公司与行业生成器 | 中 | 固定种子得到约束一致的公司池 |
| 规则、订单、账本与 T+1 批次 | 中高 | 全部资产守恒，失败订单有明确原因 |
| 聚合资金行为、成交与库存恢复 | 高 | 无玩家也有交易，玩家大单产生合理容量代价 |
| 事件链与走势解释 | 高 | 同一事件因环境不同得到可解释的差异结果 |
| 两市场共同运行 | 中 | 参数化规则可复用，同一资金不能重复花费 |
| 平衡与防刷钱 | 高、需要持续迭代 | 多种子中不存在明显自我标价漏洞，经营路线有取舍 |
| 真实跨时区、多币种与结算 | 中高、可独立延期 | 闭市、节假日与现金状态无时间套利 |

最小验证顺序：40 家公司（两市各 20）、账本与两套交易制度 → 事件/经营因素 → 多种子压力测试 → 40 股可玩原型 → 200 家与浏览器性能 → 完整用户界面。不能从“随机 K 线能画出来”推断整个模拟市场已可行；应从成交约束、事件因果与大资金退出三件事取得证据。
