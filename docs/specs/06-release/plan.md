# P6 实施计划 — 静态发布包与运行交接

状态：未开始。验收合同见 [spec](./spec.md)，切片见 [tasks](./tasks.md)。

## 进入条件

1. P5 的 RC 具有完整版本清单、运行证据和已处置的问题；正确性、数据丢失及核心流程问题已关闭。
2. P0/P4 已确定构建工具、资源基础路径、存档版本/迁移约定与浏览器支持范围。
3. 当前范围仅为单人静态 Web。托管服务与公开 URL 未确定不妨碍构建、预览、演练和交付；若以后执行公网部署，再使用当时明确的目标与权限。
4. 下文 `apps/web`、`artifacts/releases/<version>`、`artifacts/verification/p6/<run-id>` 均为计划路径，现阶段尚不存在。命令为待实施的交付合同，不表示工作区已有应用或可运行脚本。

## 实施顺序

### 1. 封装同一份可复现静态产品

- 读取 P5 RC 源版本、应用/规则/内容/存档版本、构建配置与锁文件；实现时选择明确且受版本管理的启动入口，不依赖工作区外未记载资源。
- 统一构建清单包含源修订或源快照摘要、工具/包管理器版本、锁文件摘要、构建参数、兼容存档版本、目标浏览器及文件摘要。构建时间可以记录在报告中，不注入造成无意义差异的运行资产。
- 在两个干净输出目录安装锁定依赖并构建，对比所有运行有效载荷的路径及摘要；归档压缩包时间戳差异须单独解释，不能将资产内容差异归入可忽略元数据。
- 从最终发布目录启动静态 HTTP 服务，检查页面、Worker、字体、图表、内容和相对资源路径，无开发 API、源文件绝对路径或本机端口依赖。
- 采用 P0/P5 固定的默认新局方案；如使用完整预热快照，静态包带上默认种子选择、快照版本/初始化参数和摘要，并关联与现场重算一致的证据。不能发布时遗漏快照导致默认新局退化为 60 秒预热，也不增加运行后端。
- 包内规划内容：`web/` 静态运行文件、`manifest.json` 版本/摘要、`README.md` 构建与启动、`SAVE-COMPATIBILITY.md`、`KNOWN-ISSUES.md`、`THIRD-PARTY-NOTICES` 和验证索引。具体压缩格式可按宿主选择，内容不可缺。

预计命令合同由前序实现及本阶段补齐：

```text
npm run preview:release -- --dir artifacts/releases/<version>
npm run verify:p6 -- --out artifacts/verification/p6/<run-id>
```

这些是未来脚本接口；交接时还必须写清干净构建命令与静态服务端口、基础路径和退出方式。无需依赖 `file://` 打开，Worker/存储行为应在 HTTP 环境验收。

### 2. 完成玩家资料、虚构和第三方通知

- 快速开始按“理解公开信息→选股→下单→推进→读回执→保存/继续”组织，以一个虚构例子解释两市可售规则、预算、部分成交和短线/经营取舍。
- 明确 250 日是赛季结算、世界不重置；历史预热不是玩家经历；首版没有分红、ETF、杠杆或真实金融交易。不要添加与游戏无关的冗长免责声明。
- 存档帮助说明本地存储可能受配额/清理影响，提供主动导出备份与导入恢复步骤，失败时如何保留当前档；不能把浏览器缓存描述成云备份。
- 提供版本页/反馈入口。未指定外部反馈服务时，允许复制或下载诊断摘要；摘要默认包括版本、公开种子、错误码和用户填写步骤，完整存档只由玩家主动选择导出，没有后台自动上报。
- 审核 UI、全部 200 家公司、24 模板/6 链、教程、示例存档和事件名，确认无现实市场新闻/主体直接搬用；研发来源链接可留在研发文档。
- 从锁定依赖与资产清单核对许可证和分发通知，包括图表库的实际归属要求；字体、图标及额外素材有来源记录。不得仅因依赖曾在研究中被称为开源就省略核验。
- 已知问题写可观察触发条件、影响、恢复办法及适用版本；严重问题回到实现阶段修复，不以“已知”标签放行。

### 3. 对最终包做发布冒烟与回滚演练

- 记录包摘要、服务方式、机器/浏览器版本及运行 ID；将验证关联到这份最终包，而不是开发环境或更早 RC。
- 四桌面浏览器逐项演示：新局/初始资金→两市列表与图表→同快照新闻→下单与部分成交→小时/日切换→快进取消→存档→关闭重开→跨季继续→导出/导入。真实 Safari 为必需证据，WebKit 自动化不能替代。
- 固定场景快照可缩短功能冒烟，但启动性能必须用最终包、P0/P5 相同空缓存/网络 profile 的至少 20 次默认启动：分别记录导航到首屏控件就绪和导航到默认新局可接受交易命令，桌面初值分别 p95 ≤ 3 秒与 ≤ 10 秒。确认默认配置由脚本立即执行，不含人为等待；下载默认完整快照的耗时必须计入。任意自定义种子首次现场预热的 60/180 秒预算单独复核，保留进度/取消，不能代替默认新局验收。中端移动设备复查加载、一步交易、取消、保存与恢复，不宣称全布局体验通过。
- 检查发布包版本与 P5 黄金命令流摘要一致；如仅改帮助文案/通知，则重跑对应 UI/资源及冒烟；若修改依赖、规则、序列化或存档迁移，返回 P5 运行受影响的正确性、长局和性能协议。
- 测旧兼容档、当前档、未来未知版本、损坏档和超额档。迁移对输入副本执行，完整验证后才写入新档；拒绝路径保留原快照、导出备份和用户恢复入口。

回滚演练在专用浏览器档案或存储副本中进行，不能拿用户唯一存档做试验：

1. 固定上一已验证包和其兼容存档，记录摘要；首个发布没有正式旧版时，选前序 RC/固定迁移夹具并注明演练基线。
2. 用新包加载、继续、保存，保留升级前档与新档；模拟中途更新失败时验证仍可恢复至少一份完整快照。
3. 切回旧静态包。在同存档版本可读时继续并核验；不可读时旧包明确拒绝，新档原样保留，用户可选择兼容备份或返回新包。
4. 再返回新包，确认之前新档仍可恢复。整个过程不得重发本金、重抽事件、重复结算或将失败迁移标为保存成功。

不要求建立通用发布平台。使用不可变版本目录和清楚的当前目录/链接切换步骤即可；若后来选择 CDN 或 Service Worker，需增加该环境缓存更新/回退检查，不能默认为当前已存在。

## 交付目录与证据

`artifacts/releases/<version>/` 规划存放完整静态包与交接资料；`artifacts/verification/p6/<run-id>/` 存放：

- `manifest.json`：包摘要、RC 来源、工具和验证环境。
- `results.json`、`summary.md`：逐 AC 的 pass/fail/not_run、缺失证据和最终结论，遵循总计划格式。
- `reproducible-build.md`：两次干净构建条件、文件摘要差异及判断。
- `release-smoke.md`：四桌面与移动技术回归，各步骤通过/失败/未测及证据；首屏、默认新局可交易、任意种子预热分别给出原始时长及网络/缓存条件。
- `save-compatibility.md` 与 `rollback-drill.md`：输入输出摘要、拒绝/迁移行为、回退及恢复结果。
- `fiction-and-license-review.md`：内容与第三方材料核对清单、问题处置。
- `handover.md`：本地访问方式、实际部署状态、启动/故障/备份/回滚入口和未解决问题。

全部目录在实施时生成，当前不会虚构包、URL 或运行结果。发布文档应引用相对路径以便完整搬运，面向用户的最终链接则指向实际交付位置。

## 演示与通过条件

由未参与打包的人按交接说明，在一份干净目录校验摘要、启动静态服务、完成交易并导出存档；再演示不兼容导入被拒绝、有效进度仍在，以及一次受控回滚后恢复。
P6 全部 AC 有对应证据即可交付；本地静态预览是允许的正式验收方式。公网部署若没有目标账号/域名，写“未部署，待部署目标输入”，不将整个可复现交付标为失败，也不暗示拥有公网访问地址。

## 失败处理

- 资产缺失/路径错误：修复打包并重新生成摘要，重做最终包冒烟。
- 摘要不一致：先区分运行内容差异与归档元数据，消除未记录输入，再重做两次干净构建。
- 存档/规则差异：保留输入档，回到 P4/P5 修复及复验，不能强制清空用户状态完成发布。
- 缺真实设备或试玩证据：引用 P5 未完成项并标未测；不能用文案推定兼容。P6 不重复招募已达标的 P5 试玩，除非最终包变化影响其结论。
- 仅公网目标未知：完成全部本地可验收成果；实际部署单独等待明确目标，不制造无必要的逐阶段批准步骤。
