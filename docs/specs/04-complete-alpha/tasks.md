# P4 实施任务

状态：未开始。[Spec](./spec.md) · [Plan](./plan.md) · [阶段总览](../README.md)

拆分结果：4 个纵向 Ticket。正式世界与发现机会、可恢复开局、赛季生涯、长局归档各自交付可运行能力；持久化是赛季和长局的前提，继续合并会使保存错误与经济错误无法分阶段验收。

## P4-T1 — 在完整 200 股世界发现并交易机会

状态：未开始。

### Outcome

玩家在两市各 100 股、完整正式事件内容的世界中，完成市场筛选、消息判断、下单和回执查看。

### Scope

1. 实现正式行业/规模矩阵与概念分配的约束生成，校验股份、190 关联、合法暴露和 64 次失败上限。
2. 接入冻结虚构名称/代码及业务说明词库，处理唯一性、槽位缺失、重复文本和真实实体词表检查，并保存人工审读结果。
3. 从 P3 的 8 模板/2 链扩到 24 模板/6 链，类别为 10/6/4/4；列出每个原 ID、新增 ID、分支与覆盖场景。
4. 完成市场筛选/排序、观察列表、公司详情、消息、组合、订单与回执之间的导航；历史容量与当前订单结果区分。
5. 运行生成和内容检查、各链合法分支，以及三类订单的端到端演示；继续执行 P1–P3 账本和信息回归。

### Acceptance

- 对应 P4-AC1、P4-AC2、P4-AC3；显示 200 股的同时仍使用同一个 26 钱包模型。
- 配额失败不返回残缺世界；两市展示有实际制度/政策/资金差异，不能只是主题换色。
- 完整链、消息摘要及持仓通知没有引入新的价格奖励或玩家定向灾难。

### Depends On

- P3 通过；P0 正式配额、内容与市场 profile 已冻结。

### Not Included

新资产种类、真实金融数据或额外第 25 个模板；性能发布认证在 P5。

## P4-T2 — 玩家能可靠开局、退出和恢复

状态：未开始。

### Outcome

玩家使用 P0 定案的快速默认开局，或选择任意种子现场预热；选择合法本金、保存退出后再次打开能恢复原世界，失败保存或错误导入不会损毁旧有效档。

### Scope

1. 实现固定本金/自选模式、输入校验、种子展示、P0 定案的默认快速方案，以及任意非预置种子预热进度与取消、完整缓存键和一次性入场状态。若选用静态完整预热快照，匹配版本/种子/初始化参数并证明与重算一致。
2. 定义可验证保存封套，序列化完整核心、版本与 UI 自选/标注；保持整数金额/股份和随机状态精确。
3. 实现 IndexedDB 事务检查点、上一有效备份、手动保存、日终自动保存、合并过期写入与最后成功时间展示；公开窗口暂停点保存阶段标记，恢复不先清算或重复公告。
4. 实现文件导出、临时校验后导入为新记录、切换存档；未知版本拒绝，已支持迁移必须另有前后回放证据。
5. 注入事务中断、额度不足、不可用存储、损坏与不兼容档，确认原档与内存保留；恢复后执行相同指令比较后续世界。
6. 提供首屏/默认可交易/任意种子现场预热的独立计时与采样入口；承接 P5 固定网络空缓存桌面至少 20 次默认启动、p95 ≤ 10 秒可交易和首屏 p95 ≤ 3 秒目标，另测非预置种子的桌面 60 秒/移动 180 秒现场预热预算。

### Acceptance

- 对应 P4-AC4、P4-AC5，并覆盖 P4-AC8 的自选/标注往返部分；重复初始化不会再次发放本金。
- 默认快速方案与任意种子现场预热分别可复演及测量；默认时长包含快照下载/恢复或预热，不用高级开局等待预算掩盖默认打开即玩的目标，正式性能由 P5 签收。
- 不存在“旧保存异步完成覆盖新保存”的路径；失败时不会显示已保存或重建一个看似相同的新世界。
- 可演示创建、交易、关闭/重开、导出/导入的完整操作链，版本拒绝有明确说明和原档可用证据。

### Depends On

- P3 的核心快照与图表标注；P0 版本/存储合同。可与 P4-T1 并行，最终使用其正式世界验收。

### Not Included

云同步、账号系统、存档加密或保证阻止玩家本地修改存档；没有实测迁移器则不承诺跨版本迁移。

## P4-T3 — 玩家能结算赛季并延续或结束生涯

状态：未开始。

### Outcome

第 250 日出现只读赛季成绩，玩家继续后仍在同一个世界交易；里程碑、退休和资本耗尽按生涯规则工作。

### Scope

1. 实现连续世界日到赛季/季内日映射、日终统计顺序、唯一成绩键、当季/累计指标及虚构指数比较。
2. 完成结算页、继续指令和最终记录；保持订单、冻结、锁定、事件、复核相位、保护状态与费用周期连续。
3. 实现现金 5/20/100 倍连续 5 日里程碑、净值低于原本金 1% 连续 5 日的可确认耗尽，以及暂停时主动退休。
4. 接入状态完成后的保存与错误展示，重开/恢复同一结算点不重复结算；关闭浏览器与终止生涯分开。
5. 运行 A18、A25–A28，覆盖第 248–252 日连续条件、跨季计划、甲股锁定及第 240 日附近开始的长事件。

### Acceptance

- 对应 P4-AC6、P4-AC7；成绩只读且一次写入，继续不增加现金或重置经济阶段。
- 锁定股只有下一世界日才解锁；达到现金里程碑可以继续，低现金或一笔未成交不会误判耗尽。
- 退休/确认耗尽后不能继续交易，但最终记录可读/可导出；正常退出可恢复活动生涯。

### Depends On

- P4-T2；正式内容联调使用 P4-T1 的跨季事件。

### Not Included

强制 250 日结束、赛季奖励注资、年度股票重新抽签或富可敌国的额外生涯系统。

## P4-T4 — 长局保存图表判断并交付完整 Alpha

状态：未开始。

### Outcome

玩家跨多个赛季继续经营时，历史、标注和信号不因归档或读档失真；交付带证据、可本地启动的完整 Alpha 静态构建。

### Scope

1. 实现完整日线与至少 120 日小时线的保留/归档，保存有效形态、滚动信号和手工标注锚点；旧小时区间显示归档状态。
2. 对照开启/关闭归档的同种子运行，执行 A32；保存恢复后校验信号、参考水平、确认时点和自选标注。
3. 预登记至少 3 个完整模型种子，各运行 250 日预热＋1,000 玩家日；同指令对照连续内存运行与每季重启恢复。
4. 汇总第 250/500/750/1,000 日状态、之后的下一批、锁定/事件/计划连续性及全程不变量；技术正确和经济平衡分别报告。
5. 运行 `npm run verify:p4 -- --out artifacts/verification/p4/<run-id>`，完成构建、启动/恢复说明、现场演示及 P5 移交清单。

### Acceptance

- 对应 P4-AC8、P4-AC9、P4-AC10，并汇总 P4-AC1–7；A26 的长局对照通过，P1–P3 硬规则零回归。
- 同一信号不因历史裁剪重新确认，画线不会锚到其他日期；技术长局可运行不被表述为长期盈利或全面平衡证明。
- Alpha 包可按附带步骤启动和复演；未执行的 P5 项目标明未执行，不用“待优化”掩盖失败项。

### Depends On

- P4-T1、P4-T2、P4-T3。

### Not Included

100 个保留种子的全面经济确认、完整反操纵扫描、6–8 人玩家测试或发布浏览器性能签收。
