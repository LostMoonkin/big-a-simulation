# P2 实施计划 — 先验证真实经济，再接入可玩的网页

状态：未开始。关联：[Spec](./spec.md) · [Tickets](./tasks.md) · [总实施计划](../implementation-plan.md)。

## 进入条件

1. P1 全部 AC 通过且验收包可由另一运行环境复现；公开投影、命令、推进和完整快照入口可以使用。
2. P0 已冻结两市各 20 股的行业/大小盘/概念配额、价格保护规则、基准成交筛查口径和首个浏览器范围。
3. P0 的版本清单决定框架、Canvas 图表、构建和浏览器验证工具。本计划采用 DOM + Canvas + 单 Worker 路线，不把候选库当作已经安装。
4. 所有拟建路径及命令均为计划；实现代码主要进入 `packages/sim-core`、`tools/sim-runner`、`apps/web` 和 `tests/scenarios`。

## 顺序一：以 26 个钱包运行基准世界

实现满足 P0 配额的 40 股生成器。行业、流通股份、业务暴露、初始价和概念关系都可从种子重建；无法满足配置时明确失败，不降低约束后偷偷继续。

初始化 24 个本地账户、2 个跨市场账户、固定创始持有人与服务账户。按规则分配流通股份和初始现金，风格内拆分与受约束扰动使用独立流；每个本地账户只能交易本市场，跨市场账户仍只有一个共享钱包。

实现日级需求/融资/风险因子、行业状态和公司经营扰动，以及每 20 日错峰发布的简报。公开预测基准只能读取当时公开资料；本阶段不启用突发事件，因此事件去重 A15 留到 P3，不把当前空事件集的通过当成完整覆盖。

### 基准预设 baseline-v1

| 保持不变 | 本阶段关闭/简化的项 |
|---|---|
| 26 个账户 ID、钱包、股份、风格初始份额和基础权重 | 不删除趋势/主题账户，也不把其财富转给其他账户 |
| 各风格 alpha、温度、基础持股比例、观点/评分持续噪声 | 所有角色 beta、gamma、kT、kH 置 0；主题 H 取 0，不读取技术/主题信号 |
| 目标裁切、lambda、常规复核相位和风险约束 | 不调多周期信号、不生成形态标签；周期调度是可恢复状态，不宣称多周期玩法已通过 |
| 库存股数目标、真实持有期、报价档位、小时容量和账户统一预算 | 不启用政策/事件链；经营简报变化达到规则门槛仍可触发公开复核 |
| 公开经营、错峰报告、公开估值和费用循环 | 不使用预设股价或固定每日成交量 |

将该预设保存为有版本的配置。恢复正式模型时使用另一显式预设，不能靠未记录的代码分支；任何调参都记录前后值、理由、种子清单和规则版本。

P0修订后的唯一冻结样本为 `tests/scenarios/p0/baseline-v1.json`（规则/内容0.3.1）。各风格alpha原值保持，技术/主题项置零不把账户转换为价值风格。首个原型浏览器冻结为工程基线登记的真实Windows桌面Chrome（当前154.0.8037.58），P2完整60日/交易/快进/恢复脚本在该范围签收；测试前登记完整版本，自动更新后重新绑定版本和重跑相应脚本。P5四桌面/移动责任保留。

用持续目标与真实库存产生订单，复核之外只执行剩余缺口并重报愿付/愿售价格，不每批重置目标股数。每小时容量固定并累积已成交量，重大简报不得刷新预算。接入零 ADV 的常态容量先验与每 20 日服务费用回流，完成 A16/A17。

第1轮独立fail后的单一报价候选 `npc-quote-v2-target-gap` 依[规则5.2](../../design/market-model-rules.md)使本人剩余需求/固定初始股数以±.12有界对数响应影响R_exec；原R评分、持续目标、资金/股份和所有数量/保护合同保持。先通过NPC-QUOTE-01生产固定反例/旧档分支，再用新版本新目录重新真实预热原两失败种子并运行250+5；短窗合理后原100+10全量。WorldProgress、configHash、预设与manifest绑定报价版本；旧缺字段档仍v1，不迁移、不混用旧预热。未来P3 complete也从创建采用同报价合同重新预热；不叠其他调参、不改成交硬线。

先用少量固定种子作可复现诊断，再执行阶段全量种子清单。市场枯竭先定位目标、价格分歧、预算、保护与手续费循环，禁止补造成交或临时发放现金。

明确产物：40 股生成配置、baseline-v1 参数、CLI 世界运行器、逐日经济统计和初步失败样例。对应 P2-T1、P2-AC1/AC2。

## 顺序二：浏览器从真实预热进入第一笔交易

Worker 持有一个完整世界，UI 使用 P1 的公共投影。主线程发送带 commandId 的命令，Worker 回传确认、公开版本与增量；同一结果不能因重复消息而重复入账。

新建页提供种子、默认/自选本金和创建按钮；250 日预热显示进度，可取消。完成预热后只加入一次玩家本金，进入第 1 日的公开决策窗口。取消或重试创建不能复用半个初始化状态。

最小界面包括两市行情列表、公司详情/简报、小时/日图表、账户摘要、下单区、订单/计划列表与交易回执。不画虚构“主动净流入”；上批供需或价格保护状态明确标注为历史/当前规则。

图表从批次真实成交聚合 OHLCV；零成交窗口有标记，未完成窗口不能伪装收盘。仅传当前可见股票的必要历史，不把完整私有快照复制到主线程。切股只改变订阅范围，不改变该股票是否模拟。

先交付“选一只股票—读公开简报—保护价买入—推进—看回执”闭环；公司公开字段和账户都来自权威内核，没有 UI 占位资金或随机图表。

明确产物：本地浏览器启动入口、真实预热进度、40 股列表、公司资料、两种 K 线和首笔交易脚本。对应 P2-T2、P2-AC4 及 AC5 的即时单部分。

## 顺序三：完整执行交易并恢复未完成的计划

将日单、分批计划和撤销接到同一命令入口。表单展示数量、保护价、有效期和资源预览；拒绝时保留用户可修改的输入，但不把前端校验当作最终准入判断。

账户展示总现金、可用现金、冻结现金、总持股、可售/锁定/冻结股份。回执同时显示提交参考、保护价、实际清算价、成交与余量、手续费、股份可售时间。展示最差接受价不代表保证成交。

实现文件导出/导入：要求 Worker 位于稳定暂停边界，包括公开准备完成但尚未清算的新闻决策窗口；不得为导出先执行交易。快照保留当前阶段，导入先验证，成功后整体替换当前世界与 UI 订阅，并停在原窗口，不重复公告或先推进。文件包含 NPC 状态和随机流，但页面与参与者输入仍只用公共投影，不因此开放隐藏结果。

格式或规则版本不符、内容损坏、资源不一致时保留当前世界并明确报错。本阶段不开发迁移、不伪装已经自动保存；用一次关闭重开导入演示证明恢复能力。

明确产物：三个订单入口、资源与回执面板、文件导出/导入、20 日恢复对照。对应 P2-T3、P2-AC5/AC7。

## 顺序四：交付 60 日节奏和长期基准报告

推进控件包含下一小时、下一日、指定天数快进和取消。Worker 在完整交易批次边界响应手动取消，并分段让出消息处理机会；消息触发暂停可发生在公开准备完成、NPC 下单与清算之前。不得一次阻塞执行全部 60 日而让取消无效。后台或失去焦点不产生自动时间步。

持仓重大简报暂停沿用公共窗口：先看到新资料，再允许撤改和共同清算。这里验证消息暂停的基本接口，完整模板和链式事件通知由 P3 接入。

原型第 60 玩家日收盘后进入只读摘要与暂停，仍允许导出；不发成绩奖励、不清仓、不把 60 日替换为正式 250 日赛季。CLI 可继续相同世界时钟至 250/1,000 日，此时验证的是经济与恢复，不是尚未实现的跨季产品。

基准清单在运行前固定 100 个种子和其中延长的 10 个 ID。基准使用默认 100 万本金、玩家保持持币不下单；每个世界独立预热 250 日后，运行 250 玩家日，10 个继续到 1,000 玩家日。日 20 费用周期、世界进入玩家期、价格保护与长期零成交列作重点观察边界。

按种子、市场、股票分别报告真实成交天数占比、换手中位数、最长零成交、保护受阻次数、账户现金/持仓分布及约束违规。逐种子逐市场执行“至少 90% 股票在至少 80% 日有成交”筛查初值；0.2%–5% 日换手中位数作诊断区间，偏离必须解释而不直接补造成交。不得删除失败种子或以全局均值掩盖持续停转；筛查失败须修复或经 P0 同步修订口径并全量重跑，不能用一段解释代替通过。

固定指令回放比较小时、日、快进与中途恢复；同时运行无人干预基准，区分系统枯竭与玩家巨单暂时消耗流动性。P1 不变量逐批执行，不靠最后一天余额相等判断整个过程正确。

明确产物：60 日浏览器脚本、取消/暂停证据、100+10 种子统计、失败诊断与阶段报告。对应 P2-T4、P2-AC3/AC6/AC8，并回归 P2 全部 AC。

## 核验命令与交付目录

以下命令为待实现约定，尚未运行：

```text
npm run dev
npm run verify:p1 -- --out artifacts/verification/p2/<run-id>/p1-regression
npm run verify:p2 -- --seed-manifest <manifest> --out artifacts/verification/p2/<run-id>
```

`verify:p2` 应汇总底层经济与已固定的浏览器验收脚本；需要人工步骤的结果单独注明，不能标记为自动通过。命令清单和环境以阶段 manifest 为准。

证据包包含源码/规则/内容/参数版本、seed manifest、baseline-v1 导出、逐批不变量汇总、逐种子市场指标、恢复哈希对照、UI 操作记录/关键截图、实际运行耗时及失败复现输入。耗时是基准记录，P5 才签收 200 股性能。

## 风险、失败处理与交付演示

- 基准钱股守恒但长期不成交：P2 不通过；先检查钱包集中度、目标缺口、报价分歧、小时容量及保护冲突，再回到 P0/设计修订参数并复跑全部登记种子。
- Worker 和 CLI 得到不同状态：先确认数值协议、命令边界和随机键；在差异关闭前不扩事件或内容。
- 图表不支持虚构历法或无成交标记：在 P0 已选图表的适配层解决；若无法表达合同则回报依赖选型，不伪造数据迎合图表。
- 预热较慢：记录每阶段耗时并允许取消；可以缓存完整同版本世界，但不能仅缓存 K 线并重新创建钱包。
- 用户误把受保护即时单当成必成市价单：调整表单与回执说明并重演部分成交，不改变成交合同来消除误解。

演示从空会话开始，完成预热、查看两市信息、甲买入后尝试当日卖出、乙下一批退出、日单撤销、分批未完成、暂停/快进、导出重开继续和 60 日摘要。最后查看长期基准报告中的最差种子及其诊断，而不只展示表现最好的世界。
