## 1. 进入条件与交付边界

输入为0.2玩法/精确规则、验证A01–A32、原始研究和本阶段spec。无需已有游戏代码或线上环境。模型负责人和核心工程共同对规则空白负责；Web工程可并行验证图表及公开视图合同。

本阶段预计产出以下文档/数据，路径为计划路径：`docs/design/market-identities.md`、`docs/design/engineering-baseline.md`、正式与原型配置样本、试验场景、`docs/verification/p0-baseline.md`。如修订已有规则，同步其版本与验证文档；不另建一份含相互冲突公式的“最终版”。

## 3. 市场特色定案顺序

1. 从玩家决策差异出发列两市的政策预期、公司经营、资金配置与退出风险。甲需检验政策预期到行业/概念扩散及兑现分化；乙需检验融资/利率预期、估值期限敏感度、业绩/指引与配置延续。二者均允许投机和价值行为，不规定一市永远追涨、另一市永远理性。
2. 将每条因果链写成状态、单位、更新时点、公开时点、随机输入、作用渠道和持续/失效条件。明确与现有融资因子、E_forecast及事件贡献的去重关系，不同时作为现金流和折现项重复计入同一效果。
3. 保持统一清算核心；差异落在市场参数、公开政策状态、业务暴露和资金反应。若新机制必须新增状态/现金来源，明确来源与守恒范围，不能隐含免费注资；新增可交易资产仍不在范围。
4. 复核D02。用真实资金/库存与买卖限价演算连续受阻、实际能在边界成交、无任何交叉需求三个场景。选定后的A13/A14与参考价逻辑共同更新；不以“现实如此”免除虚构规则的因果一致性。
5. 为每市场各编至少四个条件场景：相同消息下的兑现/落空、资金足够/承接枯竭等。定义资金目标、成交容量、预期版本或退出风险应如何变化；最终价格可因对手盘不同而不同。为后续“交换市场profile”的对照说明哪些差异应随profile变化。

技术形态只作为模型输出的观察指标。若某类形态需比当前4次/小时更细的交易过程，应明确首版只能表现其小时级近似或将其后置，不悄悄增加逐笔行情系统。

## 4. 原型世界与跨季场景

原型建议行业总数按正式比例缩为：甲5/4/4/3/2/2，乙2/3/2/4/4/5，各20股；各市场大小盘4/7/9。每市5无概念、11一个概念、4两个概念，共19条关系；世界共38条，可按共享八概念5/5/5/5/5/5/4/4分配。上述边际必须进一步生成可满足业务合法性和行业跨度的完整配置，不能只证明加总等于20。

使用同一个初始化规则分配26钱包及股份，行业/市值边际冲突时调整原型配置并记录，不修改正式100股配额。初始资金与单股市场容量的相对关系需记录；40股结果不能直接声称200股平衡完成。

建立跨季资料流：第240日公开线索，第255日前至少一次按规则更新公开预期，第260日以后公布结果。标出旧预期何时失效/被替换，以及第250日冻结成绩不改事件排程。另列第250日今买甲股、跨第252日计划、跨季现金里程碑的状态表。

## 5. 工程与数值试验

1. 采用[总实施计划](../implementation-plan.md)的默认栈做最小能力试验，查官方文档并锁定实际版本。试验只需固定数据展示小时/日K、无成交、MA缺历史和基本画线，以及Worker消息与静态构建；不得把固定图表当成行情模型已实现。
2. 以最大股份、市值、价格、累计资产和手续费乘法证明安全范围。优先保证账务中间量精确；BigInt与Number转换位置必须列清，存档不得因JSON转换丢精度。
3. 用固定随机键和包含边界舍入的计算输入比较CLI与可用浏览器Worker输出。确定数学近似及量化合同；未覆盖的目标浏览器写入P5验证清单，不提前宣称跨端相同。
4. 固定核心Interface及公开/私有状态样本；覆盖重复命令、旧快照下单、暂停发生在公开后清算前、恢复后不会再应用消息等情况。
5. 记录技术试验目录、运行方法、输出及弃用条件；只把需要复用的部分纳入P1/P2工程，避免试验代码成为第二套交易内核。

## 6. 验收协议冻结

经济基准以每个种子、每个市场独立报告“满足至少80%玩家日有成交的股票占比是否达到90%”；作为40股无重大事件基准的冻结出口初值，未达须修复，或回此处凭证据修订并全量重跑，不能仅解释放行。预热不计分母，零成交不补造价格。预先固定100个基准种子及其中10个长期种子，失败清单完整保存。200股全行为按环境诊断；换手0.2%–5%为诊断区间，不要求每只股票被强拉到该范围。

训练30、保留30的120日初筛与100保留250日确认分别封存名单。P2基准、P3初筛、P5最终确认不能相互冒充。P5对200股全行为模型再做预热250+玩家1000日长期检查。

性能协议必须在实现优化前注明CPU/内存/OS/浏览器版本、构建模式、股票数、种子与样本数，分别报告冷预热和缓存恢复。一日推进200ms是已有设计目标；其他启动、中断、存档和内存目标按P5协议在此定案。缺目标设备可先记录临时开发设备并给出最终测量条件，不能在测完后按结果悄悄换机或降线。

同时冻结默认新局的随机种子选择和快速初始化方案：现场计算能满足预算即可采用，否则验证随静态包分发完整预热快照的可行性。快照与规则/内容/schema版本、种子及初始化参数绑定，包含钱包、目标、随机流、事件和指标；相同输入须与重算状态一致，玩家本金仍只注入一次。预置种子清单若采用，按预先固定的随机规则生成，不看未来收益挑选；未预置种子保留现场计算路径。

按固定空缓存/网络profile至少20次默认启动，分别计导航到首屏可交互和导航到新局可接受交易命令；默认配置由脚本立即确认，下载完整快照也计时。桌面初值分别p95≤3秒、≤10秒。任意未预置种子的250日现场预热另按桌面60秒/移动180秒及进度/取消验收，不以可取消替代默认开局快速可玩。这些是待P4实现、P5/P6实测的目标；P0产物是方案、合同和方向性试验，不能写成性能已达标。

## 7. 交付演示与失败处理

演示顺序：读一个政策消息的公开数据 → 沿两市参数算出不同目标/报价意愿 → 演算有成交及无成交情况 → 展示40股配额校验 → 对照跨季状态表 → 展示数值/Worker/图表试验 → 核对D01–D08与AC证据。

如果市场差异只能靠指定股价实现，D01失败；若无供需却重开造价，D02失败；若技术试验无法保留精度/时序，D05/D06失败。保留明确失败原因和下一次决策输入；无需暂停与失败项无关的准备，但相关下游不得以临时假定进入“已完成”。

出口报告逐项给出P0-AC1至AC8的证据和结论，列明规则版本、后续需实测的初值及被替代案例。不得把技术试验PASS写成G1经济或G2玩法通过。
