# P1 Tickets

状态：四项均已实施，待独立验收。关联：[Spec](./spec.md) · [Plan](./plan.md) · [实施证据](../../verification/p1-implementation.md)。

拆分为 4 个纵向交付：单批成交、持续委托、双市场交易日、完整恢复。每个都能独立通过 CLI 演示；合并后会把账务、时序和序列化的失败混在一次不可定位的大交付中。测试与使用说明随各 Ticket 完成，不单列水平任务。

## P1-T1 — 从有限钱包完成一批真实交易

状态：已实施，待独立验收。

### Outcome

审阅者运行固定申报场景，可看到由申报算出的清算价、部分成交、费用与前后账本，全部资源守恒。

### Scope

1. 按 P0 版本建立核心包、CLI 和测试入口；建立账户、股份、订单、规则版本及整数序列化的最小可执行场景。
2. 实现有资源支持的单批买卖、统一价选取、同价账户聚合及余数分配、费用汇总和原子记账。
3. 将 A01–A05 转为真实程序的输入/期望，包含无成交、非限价内点和拆单不增加获配。
4. 编写独立整数价格穷举参考，跑至少 2,000 个固定种子的有界订单簿，保留失败种子与输入。
5. CLI 输出可读成交/余额对照和机器可读结果；拒绝无资金支持的输入，不靠初始化后补钱完成交易。

### Acceptance

- P1-AC1 通过；P1-AC5 在本 Ticket 的单批场景范围通过。
- A01 大单成交 300 股、清算 10.40，A02 小单成交 50 股、清算 10.00；A04 可在 10.50 清算。
- 调换输入顺序和同价拆单不改变账户获配/费用；两侧成交股数及含服务账户现金核对相等。
- 产物：可运行单批 CLI、A01–A05 fixtures、随机对照结果及最小账务摘要。

### Depends On

- P0 完整签收，尤其数值协议、清算顺序和稳定分配规则。

### Not Included

自主 NPC 决策、跨批日单和分批计划、浏览器页面。

## P1-T2 — 在多个批次中提交、完成和撤销交易计划

状态：已实施，待独立验收。

### Outcome

操作者可以创建三种交易委托，在资金或股份不足时收到明确拒绝，部分成交后继续或撤销，账本始终反映真实剩余资源。

### Scope

1. 实现即时单、日单、分批计划的有效期和生命周期；目标持仓缺口与玩家总量计划分开计算。
2. 实现含逐批舍入上界的冻结、成交扣除、剩余预留重算、撤单/到期一次性释放，以及同股反向单限制。
3. 实现跨两市的账户级预算检查与 NPC 意图缩量，再按实际舍入成本稳定减量；玩家超额新单明确拒绝。
4. 构造 A07–A10/A19 和部分成交后撤单、重复撤单、日末到期、拆单费用一致的连续 CLI 场景。
5. 将过程回执与订单状态一同导出；失败输入不改变已有冻结及计划。

### Acceptance

- P1-AC2 通过；P1-AC5 覆盖全部新增订单路径。
- A09 的 16 批各 1 股预留覆盖 16 分费用；A19 缩量后仍差 1 分时继续减量。
- A08 原有 40 股、成交 10 股、目标 100 股后缺口为 50，不是 40。
- 产物：持续委托 CLI 演示、生命周期快照、资源及费用回归报告。

### Depends On

- P1-T1。

## P1-T3 — 经历一个有公告和价格保护的双市场交易日

状态：已实施，待独立验收。

### Outcome

相同钱包在两个市场交易时遵守各自股份可售时点，并能解释公告后改价、保护受阻和跨日恢复的成交结果。

### Scope

1. 按固定批次阶段推进世界时钟，处理解锁、到期、公开、玩家决策和清算；同批卖款独立记录可用时点。
2. 接入只看公开快照与自身账户的小型场景参与者；以可复现公告验证 A12，禁止 NPC 抢跑和旧价保证。
3. 按 P0 冻结规则实现合法价格区间、资金有效的区间外意向、指示交叉诊断、重开公告及重新报价。
4. 跑 A06/A11/A12 和 P0 修订后的 A13/A14，加入乙市场新股本批不可再卖、下一批可售以及零成交不改价场景。
5. 分别用不同股票遍历顺序执行共享钱包场景，保存逐批成交与资源对照。

### Acceptance

- P1-AC3/AC4 通过；P1-AC5 覆盖跨日、受阻和重开过程。
- 玩家和场景参与者依据相同公共版本；旧仓可售量、新锁定量和出售款可用时点可审计。
- 产物：两市制度对照演示、公告/保护时间线和相关场景报告。

### Depends On

- P1-T2。

### Not Included

24 个事件模板、两市政策传导、真实市场规则的额外仿制。

## P1-T4 — 保存未完成交易并跨运行端精确恢复

状态：已实施，待独立验收。

### Outcome

接收者获得一份输入、快照及命令日志即可复现成交；暂停、快进、恢复和显示读取不会改变本应相同的结果。

### Scope

1. 在稳定决策边界导出/恢复完整状态，覆盖公开准备完成但尚未交易的窗口，保存当前阶段、锁定股份、订单/计划、市场保护、独立随机流及命令去重状态；恢复不重复公告或先推进交易。
2. 校验格式、规则版本、完整性和资源关系，失败不替换当前世界；不兼容版本明确拒绝。
3. 对同一指令流比较逐批、逐小时、按日推进与中途恢复；在未完成分批计划、甲锁定股份和价格保护状态时取检查点。
4. 按 P0 指定的运行端执行黄金回放，检查整数编码、状态哈希及数值一致性；验证 UI 读取和额外订单不扰乱外生随机槽位。
5. 提供 `verify:p1`、`sim:replay`、完整使用说明及阶段证据包，回归 A01–A14/A19 和所有 P1 不变量。

### Acceptance

- P1-AC6/AC7 通过，P1-AC1–AC5 全部保持通过。
- 失败报告含可复现输入、命令、版本、种子和首个分歧边界；命令失败返回非零退出码。
- 产物：可移交工程验收包、黄金快照、跨端比较结果、阶段签收摘要。

### Depends On

- P1-T3。

### Not Included

生产级浏览器自动存档、跨版本迁移和“市场长期好玩”的结论。
