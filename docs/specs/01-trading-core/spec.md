## Goal

交付可运行的无界面交易程序：输入账户、真实现金和股份、公开信息及委托指令，得到可核对的成交、费用、冻结余额和持仓变化，并能从快照恢复同一条交易过程。

用它证明统一价竞价、有限对手盘、双市场制度和确定性回放可以同时成立，为后续浏览器原型提供唯一交易内核。本阶段的演示使用固定输入场景，价格仍必须由订单计算。

## Behavior

- 一份输入可以包含两个市场、多只股票及共享钱包；每批统一冻结资源后清算，各股不会重复花同一份现金。
- 同股同批统一清算价，支持全部成交、部分成交、零成交；零成交保留最近真实价格及其时间，不创造新成交。
- 接受受保护即时单、限价日单和定量分批计划；返回提交成功、明确拒绝、成交、未成交、撤销和到期回执。
- 撤单只释放尚未使用的资源；改单按撤销旧单后提交新单处理，不能同时使用两份资源。
- 部分成交后保留正确的剩余数量和预留费用；不能把已经计入持仓的成交数量再从目标缺口中扣一次。
- 两市场共用连续世界时钟：每日 4 小时、每小时 4 批；甲新股次日可售，乙新股下一批可售，卖出款下一批可用于新单。
- 公开信息先发布，玩家决策和场景中的参与者依据同一公开快照提交，再共同清算。
- 价格区间、受阻判断和重开按 P0 冻结后的合同执行；区间外意向不是成交，也不自动获得资金支持。
- 同价按账户聚合分配；拆单、股票遍历顺序和展示刷新不改变同账户总获配与汇总费用。
- 操作者可运行一批、一小时或一天，导出快照、恢复并继续，也可按命令日志重放并比较状态摘要。
- 运行失败时保留可复现输入与失败位置，返回非零退出码；不输出成功报告掩盖账务差额。

## Constraints

- 以 P0 冻结版本及规则哈希为准；A13/A14 按已独立签收的0.3.1合同执行，原扩带/两整日语义与无交叉复位、空特别开盘反例均保持。
- 现金、股数、价格、费用及中间计算使用 P0 确定的精度与舍入协议；越界输入明确拒绝。
- 所有交易账户、固定股份持有人及服务账户纳入守恒审计；市值随价格变化，不要求市值守恒。
- 核心不依赖 DOM、墙上时钟或展示帧率；暂停、日志采样与读取公开状态不消耗市场随机数。
- 随机键依主体、用途和连续世界时点隔离；订单数量不能改变后续外生输入的随机槽位。
- 私有快照用于恢复，公开投影用于玩家与参与者输入；公开投影不能包含隐藏经营、未来事件或其他账户私有状态。
- 公开准备完成后可安全暂停和导出快照；交易清算产生的资源变更与记账必须原子提交，恢复不能停在只扣买方、尚未记卖方的中间状态。
- Python 设计算术脚本只作参考；本阶段必须在实际 TypeScript 内核上重新核验。

## Out of Scope

- 自主 NPC 选股、世界预热、完整事件库、行情形态调参和可玩网页。
- IndexedDB 自动存档、版本迁移产品、赛季成绩、结局、200 股内容和公网发布。
- 连续逐笔撮合、做空、融资、真实交易所接入、债券与衍生品。

## Acceptance Criteria

- **P1-AC1 — 清算正确：** A01–A05 在实际程序中得到规则结果；额外用至少 2,000 个固定种子的有界订单簿对照整数价格穷举，清算价、数量及双侧分配一致。输入重排与账户拆单不改变账户级结果。
- **P1-AC2 — 订单可执行：** 三类订单均覆盖部分成交、撤销、到期、重复撤销和拒绝场景；A07–A10、A19 通过，含费冻结从不超过可用资源，不重复释放或扣费。
- **P1-AC3 — 双市场结算：** A06、A11 通过；甲股份仅次日解锁，乙股份仅下一批解锁，同批跨股及跨市场卖出款不能资助新买单。
- **P1-AC4 — 信息与保护：** A12 和 P0 冻结后的 A13/A14 通过；暂停发生在公开后、清算前；保护区间与重开顺序可从日志核对，零成交不更新成交价。
- **P1-AC5 — 账务守恒：** 全部固定场景及随机订单场景逐批检查现金、股份、冻结资源、可售/锁定股份与双侧成交数量；差额、负数、重复结算均为零，拒绝输入无副作用。
- **P1-AC6 — 恢复与确定性：** 在持有未完成计划、T+1 锁定股和重开状态的场景中，连续执行、按小时/日推进、暂停导出恢复、重排股票遍历得到相同终态；P0 指定运行端的黄金回放一致。
- **P1-AC7 — 可审计交付：** 提供实际可运行命令、输入 fixtures、回放日志、关键快照、版本/参数/种子清单和逐条验收报告；任一失败返回非零退出码，无以“测试跳过”冒充通过的项目。

本阶段通过意味着交易合同已由程序验证，不意味着 NPC 经济能持续运转或游戏已经好玩。
