# 分阶段实施与交付规格

版本：1.0；日期：2026-10-01。基于玩法设计 0.2。**本目录交付的是实施规格与计划，各阶段业务实施与验收尚未完成。** 工程准备已建立React/Vite页面、TypeScript工作区、Git与设计算术工具；页面已提供固定示例数据驱动的[UI 预览](../design/ui-design.md)，尚无交易模拟器。现有可运行命令见[项目README](../../README.md)，工程初始化和 UI 预览不代表P0或P1通过。

## 目标与使用方式

交付一个可在桌面浏览器打开即玩的单人金融策略游戏：两市各100股、6行业/市、共享8概念、26个有限预算NPC，以经营配置为主，同时支持小时短线、事件判断和大资金执行。价格来自真实有效委托，玩家可以影响供需；世界信息全部虚构。正式赛季250日，历史预热另250日，可以跨季经营。

按阶段编号阅读并执行。每阶段三份文件：`spec.md`定义结果、约束和验收；`plan.md`定义实施顺序、接口、验证与交付证据；`tasks.md`把该阶段拆成少量能独立验收的实施任务。完成任务必须附其验收证据，不以代码合并、截图漂亮或运行一次无报错代替阶段通过。

- 共享实施安排：[总实施计划](implementation-plan.md)。
- 需求、设计场景和阶段对应：[验收追踪矩阵](acceptance-matrix.md)。
- 行为依据：[玩法设计](../design/gameplay-market-model.md)、[精确规则](../design/market-model-rules.md)、[模型验证](../design/model-validation.md)。
- 术语依据：[领域词汇](../../CONTEXT.md)；引擎依据：[技术研究](../research/engine-feasibility.md)。

本目录安排交付，不暗中改写金融规则。P0需要关闭的模型空白必须先形成有版本的设计修订；之后下游规格引用冻结版本。若阶段计划与冻结规则冲突，应先修订冲突文档及对应验收，不允许在代码里临时另定一套价格或资金规则。

## 范围控制

首版包含现金现货、两种股份可售规则、单一货币/时钟、小时/日K、基础均线和画线、三种订单、有限对手盘、事件、多周期资金、赛季结算和本地存档。波浪理论保留为分析视角，不实现预定浪形或自动准确数浪。

本轮计划不加入ETF、债券/期货交易、融资卖空、真实外汇/跨时区、IPO/分红/退市、多人、账号、云存档、可信联网排行榜、运行时大模型新闻生成或手机完整布局。移动设备纳入技术检查，不能因此标称手机体验完整。高阶“富可敌国”另需经济规模设计，不能用短赛季现金奖励补出来。

## 资源与估算

按从零实现、熟悉TypeScript/Web的开发者估计，1人周为5个有效工作日；包括本阶段设计、实现、对应核验和常规返工，不重复累加其他阶段的工作。以下为计划初值，未据代码吞吐量或原型结果校准。

| 阶段 | 本阶段基础人周 | 累计基础人周 | 主要投入角色 |
|---|---:|---:|---|
| P0 | 1–2 | 1–2 | 模型/玩法、核心工程 |
| P1 | 3–4 | 4–6 | 核心工程 |
| P2 | 3–5 | 7–11 | 核心工程、Web交互 |
| P3 | 5–8 | 12–19 | 模型/玩法、核心工程、Web交互 |
| P4 | 5–8 | 17–27 | Web交互、内容、核心工程 |
| P5 | 5–8 | 22–35 | 模型/玩法、核验、性能、试玩 |
| P6 | 1–2 | 23–37 | Web工程、交付 |

全链路基础约**23–37人周**，加入约30%风险余量后向上取整为**30–49人周**。这替代此前仅按大工作包给出的粗略估算，不是固定交付日期。早期“4–6人周原型”是探索投入窗口；本计划完整P0–P2包含交易正确性、250日预热和可恢复的浏览器闭环，预计7–11人周，不能沿用旧窗口承诺全部通过。

单人可以顺序实施；两名开发可分别负责模拟核心与Web交互，模型/内容/测试按阶段投入。接口冻结前不要各自实现一套市场逻辑。多人并行不消除模型校准的串行依赖，不能用总人周直接除以人数承诺日历工期。每个阶段出口根据实际返工更新剩余估算，保留变更原因。

## 通过与未通过

- 资金/股份守恒、可售规则、信息公平、重复入账与重放错误：硬性失败，修复并补对应回归证据后再推进。
- 经济与玩法筛查：40股无重大事件基准的90%股票×80%成交日为P0冻结出口，失败须修复，或回P0依据证据修订后全量重跑，不能只解释放行。200股全行为按环境诊断；其他告警线须解释和处置。不得删失败种子、偷偷降低门槛或补造资金/成交。
- 性能与兼容：按P0冻结设备及协议实测。缺少Safari实机、目标玩家或长期报告时如实列缺项，相关出口不宣称通过；不影响已经能够独立完成的工作。
- 后续阶段可先做不依赖未决行为的草图、内容草案或验证工具，但不能据此标记其核心功能完成。
