状态：未开始。[Spec](./spec.md) · [Tasks](./tasks.md) · [阶段总览](../README.md)

1. P2 已交付 40 股/26 钱包的 `baseline-v1` 浏览器原型、250 日预热、60 日操作闭环及同版本快照往返；P1 账本与清算场景通过。
2. P0 已冻结两市政策状态/传导、资金行为参数、价格带与重开程序，以及对应场景 ID 和期望结果。当前 v0.2 的待补项不视为已完成。
3. P0 已选择正式 24 模板中的 8 个代表模板和 2 条链，并明确结果分布、作用单位、报告覆盖、重大信息条件、文本槽位与分支键。
   冻结输入为[代表事件合同](../../design/event-content-contract.md)与 `tests/scenarios/p0/representative-events.json`（event-v1、规则/内容0.3.1），不是由P3现场填默认参数。生产事件引擎和自然市场验收仍归本阶段。
4. 锁定规则、参数、内容、初始化和数值舍入版本。发现合同缺项时记录具体输入及缺失答案，回到 P0 补充后继续；不得由开发者临时给价格加系数。

P2 已存在持续目标、复核相位、插值、风险及容量检查。本阶段在原排程中启用 `T_short/T_swing/T_long` 和技术/主题系数，不另写一套目标生命周期。正式完整世界与消融世界分别创建和预热。

## 实施顺序与接口

以下是拟实施位置与接口合同，不表示这些代码已经存在。沿用 P1/P2 的核心 API、包管理器和 Worker 协议；未来目录为 `packages/sim-core`、`apps/web`、`tools/sim-runner`、`tests/scenarios`。

### 1. 可解释的公开事件闭环（P3-T1）

- 在世界更新中加入候选排程、公开版本、结果替换、经营应用和报告覆盖，稳定顺序固定为连续世界时点与事件 ID。
- 内部事件保存结果和待公开分支；公共快照只输出已发布的 `eventId/version/publishedAt/expectedRange/reliability/targets/effectiveUntil` 等公开字段。
- 使用事件 ID、作用渠道和覆盖区间维护效果记录；持续效果分别保存已实现和未来部分。报告消化已实现影响后，公开增长外推剔除可识别的一次性贡献。
- 同时实现消息列表、预期版本比较和事件详情。通知筛选可以读玩家持仓；候选选择和结果抽样不可以。
- 将新闻停点接入既有 `advance` 停止条件：冻结公共版本后暂停，恢复时 NPC 与玩家共同清算；所有报价使用本次公共版本。
- 固定场景分别验证兑现、低于预期、证伪、过期、报告覆盖、部分覆盖和重复恢复，保存经济及公开预测的变化表。

### 2. 双市场政策和主题传播（P3-T2）

- 按 P0 的市场 profile 读取本地政策状态、公开更新节奏、企业暴露、估值/经营渠道及账户反应参数。公共渠道与隐藏结果的界线沿用事件合同。
- 政策冲击先更新指定世界/行业/预期状态，再走目标与委托；若一个渠道已计入公开估值，不能再次在股票价格或评分中无说明叠加相同收益。
- 实现注意力 A、扩散 B、持续性 L、方向 Outlook、公开拥挤估计及业务暴露聚合。只依赖已完成成交窗口，单个股票对扩散的贡献有上限。
- 市场和公司详情显示政策解释、业务关联和历史公开统计；不显示 NPC 精确持仓、隐藏链阶段或虚构“主动资金净流入”。
- 分别运行共同外生输入下的两市对照、单股脉冲/跨股扩散、正面兑现/落空场景。允许实际价格分化，不要求两市共享价格轨迹。
- 对 P0 市场特色场景保留参数开关的对照证据；只有资金和股份相同、仅目标行为改变的实验才算行为消融。

### 3. 多周期交易与技术观察（P3-T3）

- 从既有已完成 K 线及滚动统计计算三层趋势信号，逐项处理端点不足；未完成日线不进入日级信号。
- 把信号接到原目标评分和复核生命周期。常规/重大信息同批合并复核，之后施加风险约束，最后以保存目标与真实持仓缺口生成委托。
- 账户诊断记录复核原因、公共版本、信号窗口、插值前后目标、固定目标股数和剩余容量；诊断接口仅用于测试/开发构建，不混入正常玩家公共视图。完整存档另按恢复合同保存私有世界状态。
- 在图表增加规定 MA、水平/趋势线编辑及未完成/无成交状态；标注只引用玩家当时可见的历史。本阶段保留在会话/调试快照中，产品级持久化由 P4 接管。
- 按验证方案 4.1 实现研发形态记录：冻结突破区间、确认时点、失效、观察结束；相同前缀必须得到相同记录，后续走势只追加事实。
- 分离“条件被识别”“之后走势”“按下一可操作批次实际成交后的收益”，禁止用峰谷回看价格做基准成交。

### 4. 四条玩法与首轮对照（P3-T4）

- 将四条路径转换为只读公共快照的预注册策略，列明适用条件、入场、失效/退出、最长持有期、资金规模与保护价。
- 执行基准覆盖一次下单、限价等待、分批；策略基准覆盖持币、分散、风险/换手匹配随机、价值、事件、短线/波段、突破/回踩和主题。
- 先用固定场景判断规则，再用 30 个调参种子调整初值；冻结配置后运行另 30 个 120 日保留种子。每个世界都独立完成 250 日预热。
- 记录两市、大小盘、小时/日尺度的形态样本、识别延迟、等待、成交率、成本、收益和风险；固定技术场景不能代替自然市场出现率报告。
- 进行消息、概念关系、技术项/复核频率、持有期、资源约束消融；涉及故意去掉约束的实验只作为离线研发对照，不进入正常游戏模式。
- 若查看保留结果后调参，该组种子转为调参集，另建保留集重跑受影响比较；不能反复挑选漂亮种子补齐成功案例。

## 状态与 UI 流

| 状态/页面 | 玩家操作与转移 | 必须保持的状态 |
|---|---|---|
| 公开窗口暂停 | 查看消息及旧预期、检查两市影响、撤改/提交、继续 | 同一公共快照；未清算订单；未公开分支不暴露 |
| 股票/主题详情 | 比较业务关联、成员扩散、MA 与既有标注 | 图表读取不推进时钟，不重抽噪声 |
| 连续快进 | 在已有新闻/风险条件停点返回决策 | 小时预算、持续目标和复核相位不重置 |
| 交易回执 | 查看实际数量/费用/可售时间和判断失效 | 单批同价；容量统计为历史，不承诺当前成交 |
| 研发复盘 | 检查因果链与确认时点，切换对照结果 | 隐藏诊断与正常玩家公共视图隔离 |

## 验证流程与证据

计划入口为 `npm run verify:p3 -- --out artifacts/verification/p3/<run-id>`；批量入口为 `npm run sim:batch -- --manifest <manifest> --out <dir>`。这些命令在实施时提供，目前文档不代表命令已经存在。每次运行生成独立证据目录，不覆盖旧 run；至少包含：

- `manifest.json`：源码 hash 或 commit、构建、规则/内容/保存版本、配置与种子清单 hash、参数、运行环境、预热与玩家日数、执行命令。
- `results.json`、`summary.md`：沿用总实施计划的逐场景 pass/fail/not_run、度量、失败/缺失项、参数改动和阶段结论。
- `acceptance.json`：P3-AC1–10 与场景对应的通过/失败/未执行，不以缺日志表示通过。
- `event-traces.jsonl`、`decision-traces.jsonl`：A12/A15/A20–A24 及 P0 双市场合同的完整前后状态摘要；隐藏轨迹不得打包入公开 UI。
- `technical-signals.jsonl`：A29–A31 与成立/失败固定场景，包含识别当时的历史截止点。
- `strategy-report.md` 及机器可读结果：训练/保留划分、配对结果与区间、执行成本、等待、消融差异、失败和阶段结论。
- `demo.md`：可复现种子、公共事件、操作批次、录屏/截图路径和四条玩法的失败解释。

按“固定场景→P1/P2 回归→浏览器脚本→保留初筛”的顺序执行。账务、信息公平或未来泄露失败时停止玩法评分，先修复并重跑依赖场景。P3 的证据由 P5 扩展确认，不替代公开版验收。

## 现场演示脚本

1. 创建完整模型世界并完成预热，进入公开预告时点；展示当时预期，提交计划，继续到结果，比较甲/乙可售时点及共同清算。
2. 在同一题材场景展示单股脉冲不等于扩散、三家成员扩散及结果落空后的减仓；从消息记录定位每次变化依据。
3. 打开同股小时/日图，画参考水平；展示短线与波段信号分歧，以及突破随后失败的确认顺序。切换视图前后状态摘要不变。
4. 用固定种子和相同外生流比较小额、大额及分批订单，展示真实未成交和成本；播放经营修复失败、事件低预期、趋势反转的回放。
5. 展示四条路径的保留样本结果、适用条件及失败种子。没有自然出现样本的类别明确显示“证据不足”。

## 失败处理与退出标准

- 若事件重复计入、公共快照泄露或多周期复核失真，作为实现缺陷阻塞本阶段，不能靠调小事件幅度掩盖。
- 若行情长期缺少有效交易、角色实际行为同质或四条路径无法形成取舍，回到行为/初始化参数与公开反馈调整；保留改动前后证据。
- 双市场没有可观测差异时区分合同缺失与实现错误：前者回 P0，后者在 P3 修复；不得直接插入“甲市必炒题材”的行情脚本。
- P3 全部硬性 AC 通过、四条路径取得可复盘初筛证据后进入 P4。策略仍可能亏损，数值初筛通过不等于长期平衡通过。
