### 诊断恢复与跨平台来源

运行器 `--resume yes` 只复用来源和清单完全相同的**已完成种子**，包括完成的失败种子；未完成种子从创建重跑，不支持从第 1,024 批接着执行。逻辑见 [p2-batch.mjs](../../tools/sim-runner/p2-batch.mjs)。在旧环境继续之前应先复制中断进度作历史记录；不要覆盖唯一证据。

干净的新环境优先在新输出目录重现原两种子，避免缺快照与原始文件行尾差异被误判为可续跑：

```powershell
# 由实施/实验子代理执行；本次交接没有执行此命令。
npm.cmd run sim:batch -- --manifest tests/scenarios/p2/diagnostic-manifest.json --out artifacts/verification/p2/diagnostic-04-reproduced --jobs 1
```

来源 hash 是原始文件字节 hash。旧 Windows `core.autocrlf=true`，其他环境可能因 LF/CRLF 产生不同身份；须逐文件核对差异，不可直接改旧 manifest 的预期 hash 绕过冻结检查。用新目录和新 manifest 记录新环境身份，保留本提交的历史来源。不要仅为消除 hash 差异而大范围改动代码或黄金文件。

资源初始先用 `--jobs 1`，确认实际运行与资源后再决定全量并发；不要复制 README 的 `--jobs 4` 当作实测安全值。当前只有 Windows 小样本时序，没有证明死机原因。普通 shell 在旧环境出现 `apply deny-read ACLs` 初始化错误，带明确理由的 `require_escalated` 本地命令曾可执行；这属于旧环境工具情况，新环境先正常尝试，不必预先申请全局权限。
